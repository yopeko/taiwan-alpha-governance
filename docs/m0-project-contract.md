## 2. 產品目的及非目標

### 2.1 目的

建立以官方資料、Point-in-time 證據及受控策略升級為核心的台股研究與決策平台。AlphaMaster 用於產生研究候選；台股核心負責市場真實性、驗證、帳本及治理。

### 2.2 第一階段非目標

- 不承諾以 NT$10,000 產生穩定收入。
- 不做高頻、當沖、融資、融券、借券或槓桿交易。
- 不做無人監督的券商自動下單。
- 不使用 LLM 或不透明情緒分數批准策略。
- 不因較高樣本內報酬、Sharpe、IC 或較多候選而宣稱策略進步。

## 4. 官方資料與證據契約

### 4.1 來源優先順序

1. TWSE、TPEx、MOPS 官方 API、網站或正式檔案。
2. 台灣主管機關及官方法規系統。
3. 券商契約與官方 API 文件。
4. 授權資料供應商。
5. 社群、爬取、推估或免費非官方來源，只能作明示的研究 fallback。

### 4.2 每次資料取得必存欄位

- 來源機構及端點或 URL；
- 查詢參數；
- 抓取開始及完成時間；
- 資料所屬日期或期間；
- 原始 payload 或不可變快照位置；
- 內容 SHA-256；
- parser 名稱及版本；
- HTTP 或來源狀態；
- 完整、缺漏、延遲、修正版或 fallback 證據狀態；
- 首次觀察時間及修正時間。

缺少追溯欄位的資料不得進入 `formal` 驗證。

### 4.3 Point-in-time 規則

- 財報、月營收、事件及研究註記只能在當時已公布後使用。
- 保存所屬期間、官方公布時間、首次取得時間、修正時間及來源紀錄。
- 不把後來修正版覆寫為過去當時可見值。
- 不推算無證據的精確申報時間；保守日期須標示來源和限制。
- 缺值、停牌、下市、新上市及限制交易皆是資料狀態，不得前值填補為可交易。
- 原始官方價格不可因後來公司行動被改寫；調整價格必須是可重建的衍生資料。

### 4.4 新聞與軟性資訊

新聞、重大訊息、公司治理、領導階層及催化劑至少保存來源、URL、時間、標題、摘要及歸因。無法穩定驗證的內容保留為 `research-only` 或 `assumption`，不得默默加入正式分數。

AI 可以摘要或解釋，但無權：

- 改變正式分數；
- 批准候選；
- 改變資金或部位；
- 產生或送出真實委託。

| 不完整市場 | 任一市場延遲、缺漏或日期不一致即 fail closed |

| 精確零股成交 | 沒有零股或券商成交觀察時不得聲稱精確；必須保留 no-fill 與 partial-fill 狀態 |
| 重跑 | 同一資料快照、策略版本與日期必須冪等，不得產生第二個不同決策 |

目前官方規則核對顯示，集中市場一般撮合為 09:00 至 13:30，普通股票一般交易單位為 1,000 股，一般股票通常採基準價上下 10% 限制；盤中零股為 1 至 999 股，09:10 第一次撮合，其後每 5 秒集合競價，限電子限價 ROD 且不得信用交易或借券賣出。零股成交價不構成普通交易 OHLC。規則來源及核對日期見 [來源登錄表](evidence/source-register.md)。

交割採 T+2。這只定義款券交割時點，不得直接複製 A 股「當日買進不可賣出」的 T+1 邏輯。

## 6. 回測與執行帳本契約

正式驗證不得只計算 `position * return - proportional_cost`。至少維護：

- NTD 現金；
- 待交割款券；
- 整數股數庫存；
- 平均成本；
- 委託、拒絕、失效、取消、部分成交及成交；
- 已實現及未實現損益；
- 手續費、最低手續費、證交稅、價差與滑價；
- 每日 NAV、高水位及回撤；
- 無法成交原因及使用的市場規則版本。

帳本不變量：

1. 現金、待交割項目與市值相加必須等於 NAV。
2. 只做多模式下股數不得為負，且必須是整數。
3. 非交易日、停牌或不合資格狀態不得成交。
4. 每筆費用及稅額可回溯至 order 或 fill。
5. 未授權的待交割資金不得被當成購買力。
6. 重複執行不得重複成交或重複扣款。

## 7. 成本模型

### 7.1 已驗證項目

- 一般公司股票賣出證券交易稅：成交價的 0.3%。
- 符合規定的現股當沖 0.15% 優惠目前法規列至 2027-12-31，但初始政策禁止依賴當沖。

### 7.2 研究預設假設

在券商契約未提供前，研究報告使用下列保守參數，並明確標示 `assumption`：

| 參數 | 預設值 | 用途 |
|---|---:|---|
| 買賣手續費率 | 每側 0.1425% | 未套用電子折扣的研究基準 |
| 最低手續費 | 每筆或每次計費 NT$20 | TWSE 教育案例；不是所有券商共同條款 |
| 賣出股票交易稅 | 0.3% | 一般股票 |
| 基準滑價 | 每側 0.20% | 日線及零股保守研究假設 |
| 壓力測試 | 可變成本及滑價的 1.5、2、3 倍 | 評估脆弱性 |

所有候選必須在相同成本模型下比較並通過至少 2 倍成本壓力後，才可由 `research` 申請進入 `validated`。

**真實 canary 在取得下列兩項前為 `blocked`（`m0-v1.3.0`，[D18](evidence/m3-owner-decision-d18-2026-08-28.md)）：**

1. **官方收費標準 PDF 存檔**（**已於 2026-08-29 滿足**，`f95ddd84…`），**加上一份把本帳戶與其實際適用費率連起來的文件**（**未滿足，且尚不知是否存在**）。
2. **零股成交證據**——一筆零股委託在當時會不會成交。日線資料答不出這件事。

### 報告的預設成本基礎是牌告條款（`m0-v1.4.0`，[D19](evidence/m3-owner-decision-d19-2026-08-29.md)）

**所有候選報告與比較的預設成本基礎為：手續費率 1.425‰、最低收費每筆 20 元、無折讓。**

依 2026 優惠條款計價的任何數字**必須明確標示，且不得作為預設**。

理由：在 §8 的風險政策下，NT$904 部位的來回成本在牌告下是 **4.67%**（證據為有雜湊的封存 PDF），在優惠下是 **0.44%**（證據為頁面截圖的轉錄，且**沒有任何文件把該優惠連到本帳戶**）。**一份沒有文件把它連到本帳戶的十倍優勢，不該是任何結論的預設前提。**

### 封鎖條件不得建立在未經檢視的文件內容上

> 任何封鎖條件若以「某份文件會載明某事」為前提，**該前提必須先經檢視**。未檢視前，該條件寫成「取得並檢視文件 X，確認其是否載明 Y」，而不是「取得載明 Y 的文件 X」。

v1.2.0 假設簽署契約會載有優惠條款——優惠不進開戶總約。v1.3.0 假設開戶通知信會載明專案費率——它是同一份牌告。**兩次的後果不同，成因相同。**

### 為什麼第一項不是「簽署契約」

`m0-v1.2.0` 寫的是「簽署的券商條款」。2026-08-28 查明：**開戶時簽的是開戶契約總約，而變動性的限時行銷優惠不會寫進固定條款**，其效力來自官方公開的費率公告與活動網頁。

也就是說，一份載有優惠條款的簽署契約**不是一個可以取得的東西**。

**一個指向不存在物件的封鎖條件，與一個宣告自己條件已滿足的封鎖條件同樣壞。** 前者永遠不會解除，後者會被隨手解除，而 v1.2.0 存在的理由正是修掉後者。

**本專案在券商條款上可取得的證據上限，是發布者公告加帳戶確認，不是契約。** 這句話寫下來比留一個永遠達不到的門檻誠實。

v1.1.0 以前此處寫的是「取得實際券商費率、最低費用及零股計費規則前為 `blocked`」。那三項於 2026-08-25 全部取得（[D14／D15](evidence/m3-owner-decisions-d14-d15-2026-08-25.md)，條款落於 `scripts/lib/broker_terms.py`），照原措辭字面讀，M10 就該解除——而**實際擋住 canary 的從來不是費率**。原措辭把費率問題與成交問題寫進了同一句。

## 8. NT$10,000 資金與風險政策

| 項目 | M0 基線 |
|---|---:|
| 初始資金 | NT$10,000 |
| 用途 | 流程驗證，不是收入目標 |
| 最大持股數 | **10**（v1.1.0；原為 2）|
| 單檔 NAV 上限 | 45% |
| 最低現金保留 | 10% |
| 單筆計畫風險目標 | 0.75% NAV |
| 單筆硬風險上限 | 1.00% NAV |
| 總開放風險上限 | **7.50% NAV**（v1.1.0；原為 2.00%）|
| 委託 | 零股限價 ROD；實際方式須符合券商 |
| 再平衡 | 原則每週或重大訊號變化；不得為微小排名變化頻繁換股 |
| 槓桿、融資、放空、借券、當沖 | 0；禁止 |

若整數股數、價格、停損距離及成本無法同時滿足風險上限，結果必須是 `no_trade`，不可向上取整後突破上限。

**最大持股數不是獨立參數。** 它等於總開放風險上限除以單筆計畫風險（7.50% ÷ 0.75% = 10）。兩者必須一起變動，否則一道閘門會允許另一道閘門禁止的事。

**總開放風險上限刻意低於 §8.1 的 8% 硬停止門檻。** 上限若等於或高於硬停止，一組完全合規的部位在停損全數觸及時會直接觸發硬停止——風險政策允許的狀態，停止規則不允許。授權額度為 10% 以內，取 7.50% 以留出這段間隙。

變更理由與證據見 [Owner 決定 D16](evidence/m3-owner-decision-d16-2026-08-25.md)。

### 8.1 風險降低與停止規則

- 任一來源日期不一致、資料品質阻擋或市場狀態不明：停止新決策。
- 帳本不平、重複 order/fill、策略版本無法解析：立即停止所有新委託。
- 紙上／canary NAV 自高水位回撤達 5%：轉 `watchlist` 並停止新部位，等待人工稽核。
- Canary 回撤達 8%：硬停止、取消可取消委託並要求人工決定是否退回 paper。
- 實際成本、拒單率或滑價超出核准範圍：只允許減少或停止風險。

5% 與 8% 是第一版治理門檻，狀態為 `baseline-approved-for-planning`；M7 後可提出替代值，但增加風險必須用相同 OOS 協定驗證及人工批准。

## 9. 策略軌道及生命週期

| 軌道 | 用途 | 可否影響真實資金 |
|---|---|---|
| `research-sandbox` | 自由研究、AlphaMaster 候選、未驗證資料 | 否 |
| `challenger` | 使用固定協定與 champion 比較 | 否 |
| `formal` | 已通過完整升級門檻的不可變策略版本 | 僅在 canary／formal 另獲人工批准後 |

允許的前進方向只有：

`idea -> research -> validated -> shadow -> paper -> canary -> formal`

`formal` 可因警報轉入 `watchlist`，經稽核後恢復或退役。退役策略要重新啟用必須回到新的研究循環。

### 9.1 固定比較與 OOS 邊界

每一個 challenger 必須使用相同的：

- 歷史日期及 Point-in-time 股票池；
- 初始資金、持股數、再平衡時間及交易限制；
- 成本、滑價、拒單及成交模型；
- walk-forward folds、gap／purge 及 sealed OOS；
- 報酬、回撤、成本、容量及曝險報表。

最低比較組包含現金、適當市場指數或 ETF benchmark、合資格股票池等權、equal-size same-pool random selection、簡單動能／相對強度策略、目前 champion 及 challenger。

使用 `training -> validation -> gap/purge -> sealed OOS`。任何已被查看並用於選模的 OOS 不得繼續標為 sealed OOS。一次只改一個主要假說，按策略 family 及 funnel stage 稽核，使用同一協定重跑。更多候選、較高樣本內分數或單一好年份不是升級證據。

### 9.2 時間觀察門檻

- `validated -> shadow`：策略 artifact 必須先凍結；shadow 至少觀察 60 個交易日。
- `shadow -> paper`：資料到達、訊號時間與 no-trade 原因穩定後才可進入；paper 至少觀察 60 個交易日。
- `paper -> canary`：除上述時間外，需有拒單、partial fill、延遲、滑價、成本、停止及 rollback 證據與人工批准。
- `canary -> formal`：原則至少觀察 60 個交易日；若交易數不足則延長，不得把沒有交易當成成功。任何替代門檻都需事前核准。

歷史回測不得取代 shadow、paper 或 canary 的即時資料與成交觀察，也不得跳過任何狀態。

本專案目前狀態：

- 真實資金 formal strategy：`none`。
- AlphaMaster 公式：一律 `research-only`。
- 既有 `tw-sepa-screener` 紙上策略：外部既有能力，不因 M0/M1 自動成為本專案 formal strategy。

## 10. 明確禁止事項

- 使用今天的股票清單回測過去。
- 以未記錄方法的調整價取代原始官方價。
- 將缺值、停牌或下市以 forward-fill 變成可交易。
- 假設所有零股限價委託可在收盤或次日開盤完整成交。
- 忽略最低手續費、賣出稅、滑價、拒單或部分成交。
- 在同一反覆檢視的驗證資料上選模並宣稱為 OOS。
- 讓研究腳本覆寫正式策略檔。
- 依近期 Sharpe 或單一好年份自動放大風險。
- 自動把研究候選升級為紙上、canary、formal 或 live。
- 讓 AI 新聞分析直接變更評分、部位或委託。
- 未經台股差異稽核直接合併 AlphaMaster A 股 PR。

## 11. 責任分工

| 角色 | 責任 | 最終權限 |
|---|---|---|
| Product Owner | 市場、資金、商品與優先順序 | 批准範圍變更 |
| Data Steward | 官方來源、追溯、Point-in-time、資料品質 | 阻擋不合格資料 |
| Research Owner | AlphaMaster 候選與實驗 | 只能提交 `research-only` |
| Validation Owner | 固定 OOS、基準、成本與偏誤稽核 | 批准進入 `validated` |
| Risk Owner | 資金、曝險、停止及回退 | 可降低或停止風險 |
