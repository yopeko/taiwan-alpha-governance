# 判斷式研究契約

| 欄位 | 值 |
|---|---|
| 契約版本 | `discretionary-research-v1.0.0`（2026-09-02）|
| 狀態 | `baseline-approved`，2026-09-02 |
| 用途 | 定義一次由人做出的決策要記什麼、怎麼被對照、以及怎麼判它成功或失敗 |
| 核准 | Product Owner（單一簽核人），[D23](../evidence/m3-owner-decision-d23-2026-09-02.md) |

## 0. 這份契約要防的一件事

**「賺錢了」不等於「判斷對了」。**

一個獲利的部位有四種來源：判斷正確、大盤上漲、隨機運氣、或以上任意組合。**沒有機制的話這四者無法分辨**，而人天生會把它們全部記成第一種。

量化那一側有封存樣本外與隨機對照可以量。判斷式研究面對**一模一樣的自欺風險，而且沒有回測**。

**本契約把量化那側已建成的機制，改造成判斷式決策也能用的形式。**

## 1. 一次決策分兩個階段，兩次寫入

登錄檔 `decision_journal.jsonl`，**append-only**。

### 1.1 `thesis` 階段——必須在下單之前

| 欄位 | 說明 |
|---|---|
| `decision_id` | 流水識別，如 `d-001` |
| `stage` | `"thesis"` |
| `recorded_at` | 登錄時間 |
| `code_commit` | 登錄時的 git commit。**工作樹必須乾淨** |
| `market`、`symbol` | 標的 |
| `thesis` | 為什麼會漲 |
| `falsifier` | **什麼可觀察的事件發生就代表我錯了**。見 §2 |
| `horizon_sessions` | 論點應在多少個場次內兌現 |
| `target` | 論點達成長什麼樣 |
| `exit_rules` | 允許的出場條件，見 §4 |
| `universe_snapshot` | 當日可交易股票池的識別與雜湊，見 §3.2 |
| `considered_not_bought` | 看過但沒買的清單，見 §5 |

### 1.2 `outcome` 階段——出場之後

| 欄位 | 說明 |
|---|---|
| `stage` | `"outcome"` |
| `decision_id` | 對應的 thesis |
| `entry_session`、`exit_session` | 實際區間 |
| `exit_reason` | 必須是 §4 四者之一 |
| `thesis_held` | 布林。**論點是否成立**，與損益分開判 |
| `thesis_evidence` | 為什麼判它成立或不成立 |
| `falsifier_fired` | 布林。事先寫下的否證事件是否發生 |

**`thesis_held` 與損益是兩個欄位，永遠不得由其中一個推出另一個。**

## 2. `falsifier` 不得是價格

**「跌 20% 就是我錯了」不是論點的否證，那是停損。**

兩者都要有，但它們回答不同的問題：停損管的是虧多少，否證管的是**我對這家公司的理解錯了沒有**。

合格的否證條件是**可觀察的事件**：

- 毛利率連續兩季低於 35%
- 該筆訂單未在 Q3 認列
- 主要客戶轉單
- 產能擴充遞延超過兩季

**登錄器拒絕含有價格門檻語意的 `falsifier`**（如「跌」「%」「停損」「股價」）。這是一道粗糙的守門，會有誤判；**誤判時應改寫 `falsifier` 而不是繞過它**——一個可以被繞過的守門等於沒有守門。

## 3. 對照組：兩個，都不消耗封存區

### 3.1 為什麼不需要封存樣本外

**判斷式決策是對未來做的，本質即樣本外。** 論點寫於 D 日、判定於 E 日，而 E 日的資料在 D 日不存在。

**時間免費提供樣本外，且不需要任何人裁決。** [巢狀驗證契約](nested-validation-contract.md) §6 記著封存區只有 382 個場次且不會再生——**本軌道結構上不會用到它**。

### 3.2 隨機同池籃子對照

在 D 日買進 k 檔、持有到 E 日：

1. 從 **D 日的可交易股票池**（研究資料集 `tradability_state == eligible`）隨機抽 k 檔
2. 同樣持有到 E 日，套用**同一套成本模型**
3. 用**預先寫死的 20 個種子**抽 20 個籃子
4. 呈報：你的 k 檔的報酬落在那 20 個的**第幾百分位**

**種子沿用[對照計畫 001](../evidence/m7-control-plan-001-random-selection-2026-09-01.md) §1.2 的費氏數列前 20 項**，選它的唯一理由是它在本契約之前就存在。

**兩條不可違反的細節：**

- **母體必須是買進當天的股票池，不是事後的。** 事後抽會漏掉期間內下市的公司，那是倖存者偏誤——而 M3 的 lane 設計就是為了讓這件事可查
- **`universe_snapshot` 必須在 thesis 階段就記錄並帶雜湊。** 出場後才決定母體等於選對照組

### 3.3 等權股票池基準

同一區間、同一成本模型，**整個可交易股票池等權持有**的報酬。

**比市值加權指數更適合**：指數會被單一權值股主導，等權池才是「隨便買」的真實對照。

這正是 [M0 §9.1](../m0-project-contract.md) 要求的「合資格股票池等權」那一欄。

### 3.4 三個數字必須並排呈報

```
你的組合          +30%
隨機 20 籃 中位    +28%
可交易池 等權      +26%
```

**任一缺席即不算完成一次判定。** 只報自己的報酬，就是回到本契約 §0 要防的那件事。

## 4. 出場規則必須事先寫死

否則「我覺得該賣了」使前述所有對照失效——**一個可以事後決定何時結束的實驗，無法被否證**。

只允許四種：

| # | 出場理由 | 條件 |
|---|---|---|
| 一 | `thesis-falsified` | 事先定義的否證事件發生 |
| 二 | `thesis-achieved` | 事先定義的目標達成 |
| 三 | `horizon-reached` | `horizon_sessions` 到期 |
| 四 | `risk-rule` | M0 §8.1 的停止規則觸發 |

**「我改變主意了」不是出場理由，是一次新的決策，要寫新的論點。**

登錄器拒絕不屬於這四者的 `exit_reason`。

## 5. 未買清單

**看過但沒買的，也要記在 thesis 階段。**

研究了 40 檔買了 8 檔，那 32 檔就是「選股動作」的對照組。**若那 32 檔在同區間的報酬中位高於買進的 8 檔，選股是負貢獻**——不如買研究過的全部。

這是[試驗登錄契約](trial-ledger-contract.md) §0 的直接類比，而那句話原封不動適用：**沒有被記錄的那些，正是最可能不利的那些。**

`considered_not_bought` 允許為空，但**必須明確為空陣列而不是缺欄位**——「這次沒有看別的」與「這次忘了記」在摘要裡長得一樣。

## 6. 判定：論點 × 損益，兩個軸

|  | 賺錢 | 賠錢 |
|---|---|---|
| **論點成立** | 技能 | 論點對但被別的東西蓋過（通常是大盤或時機）|
| **論點不成立** | ⚠️ **運氣** | 正確地被懲罰 |

**左下角那格是本契約存在的主要理由。** 判斷式研究的人系統性地不記錄它——賺錢了就沒有人回頭問論點對不對。

**`thesis_held` 必須在看到損益之前判定，或至少獨立於它判定，並寫下 `thesis_evidence`。**

## 7. 本軌道自己的否決判準

**20 次完成的決策後，下列任一成立即應否決或大幅修改本軌道：**

| # | 判準 |
|---|---|
| 一 | 論點命中率 ≤ 50%（等同擲硬幣）|
| 二 | 相對隨機籃子的**中位百分位 ≤ 50**（選股沒有加值）|
| 三 | 未買清單的報酬**中位高於**買進清單（選股是負貢獻）|

**判準訂在過程不訂在損益**：過程 2–3 年會說話，報酬邊際要 6 年以上（[提案 002](../evidence/m7-proposal-002-discretionary-track-2026-09-02.md) §8）。

**不主張統計顯著性。** 20 次撐不起 p 值；判準二取「中位百分位 ≤ 50」是一個可以被字面查證的事實。

## 8. 唯一不能靠自律的那一條

**`thesis` 的 commit 時戳必須早於下單。**

只要有一次「先買了，回頭補寫理由」，整套就退化成事後合理化——**而且它不會留下痕跡**。

這與[巢狀驗證契約](nested-validation-contract.md) §3.1 是同一條機械證據：`candidate_commit` 必須早於評估，而 M6.3 那次做不到，只能靠自述。

**其餘工具都能事後補救，這一條不能。**

## 9. 登錄器的拒絕條件

`record_decision.py` 在下列任一情況拒絕：

1. **工作樹不乾淨。** `code_commit` 要指認寫論點時的那份程式碼與文件
2. **`falsifier` 含價格門檻語意**（§2）
3. **`exit_reason` 不屬於四者之一**（§4）
4. **`outcome` 階段找不到對應的 `thesis`**
5. **同一個 `decision_id` 重複寫入同一階段**——登錄是 append-only，修正要開新的 `decision_id` 並在其中指認被修正者
6. **`thesis` 階段缺 `universe_snapshot`**（§3.2）
7. **`considered_not_bought` 缺欄位**（空陣列可以，缺欄位不行，§5）

## 10. 這份契約不涵蓋

- **不涵蓋「該買什麼」。** 這是判讀機制，不是選股方法
- **不涵蓋 M0 §8 的任何豁免。** 資金、名額、45% 單檔、7.50% 總開放風險全部適用
- **不涵蓋績效承諾。** §7 已說明樣本數的限制
- **不取代量化軌道。** 兩者並行，共用同一套資料、成本模型與帳本
- **不涉及封存區**（§3.1）
