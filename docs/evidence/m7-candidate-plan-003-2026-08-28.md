# 候選計畫 003：拿掉突破，讓排序第一次獨立被量（2026-08-28）

**狀態：`planned`。本文件必須在任何一次執行之前提交。**

依[對照比較契約](../contracts/control-comparison-contract.md) §4 與[試驗登錄契約](../contracts/trial-ledger-contract.md)。

**此刻沒有任何結果存在。** 本文件的用途就是在結果存在之前把話說完。

## 0. 為什麼這是下一個候選

### 前九次試驗換的都是同一個旋鈕

到 2026-08-28 為止，每一個候選都是：

> **20 日突破進場 + 8% 停損 + 20 場次持有上限**，只換排序函式。

而排序被證明影響不大——[比較 001](m7-comparison-001-result-2026-08-28.md) 的登錄結果是動能與低波動誰都沒有勝出。

**進場規則從頭到尾沒有變過，也從頭到尾沒有被論證過。**

那個 20 日突破是 M6 Phase 3 為了驗證管線隨手選的探針。它的 docstring 到今天還寫著「a probe for the pipeline, not a proposal」——**而我們用它跑了九次，每次只換旁邊的旋鈕。**

### 而它讓排序無法被乾淨地量

現有設計裡，排序只能對**已經通過突破篩選的訊號**重新排列。突破訊號少、雜、且依 [M6.2](m6-2-rotation-feasibility-2026-08-26.md) 的量測每天重洗（平均 8.72 檔／場次）。

所以「排序有沒有用」這個問題被問了兩次都答不出來，不是因為排序沒用，是因為**它被突破篩選攪在一起**。

拿掉突破，排序第一次可以獨立被量。

## 1. 候選定義

| | |
|---|---|
| 候選 id | `rank-only-momentum-12-1` |
| 進場 | **無進場條件**。每個再平衡日持有分數最高的 N 檔 |
| 排序 | `momentum-12-1` |
| 再平衡 | 每 21 個場次（一個月）|
| 名額 N | 10（M0 §8，不變）|
| 停損 | 8%（不變）|
| 持有上限 | 無。部位持有至它掉出前 N 名或觸及停損 |
| 股票池 | `all` |

**唯一與候選 A（M6.3 的 `momentum-12-1`）不同的是進場規則。** 排序函式、名額、停損、資金規模全部相同。

### 這是動能文獻的原始形狀

Jegadeesh & Titman (1993) 測的就是「依過去報酬排序、取前若干、定期再平衡」。**不是「突破之後再依過去報酬排序」**——後者是本專案自己組出來的東西。

所以這個候選比先前的更接近先驗：它少了一層本專案添加的結構。

## 2. 預期哪個方向會贏

**沒有預期，但這次的「沒有預期」與比較 001 的不同。**

比較 001 我寫「兩個方向的故事都編得出來」。這次不是那樣——這次我對**報酬**沒有預期，但對**週轉**有一個明確的、可以被否證的預期：

> 月再平衡的週轉應顯著低於突破進場。M6.2 量到突破的換入是 8.72 檔／場次；月再平衡的上限是 10 檔／21 場次 = 0.48 檔／場次，**低一個數量級以上**。

**這個預期若不成立，代表我對這個設計的理解是錯的**，而那比報酬數字更值得知道。它寫在這裡就是為了能被否證。

## 3. 什麼結果會被算作「沒有幫助」

判定只看**參考衡量規模**（ADR-0002 決策 1）。對照組是 M6.3 的 `momentum-12-1`（突破進場、同排序）。

**「候選 003 勝過 M6.3 候選」須同時滿足：**

1. 兩個參與率下，003 的窗口內報酬皆高於對照；且
2. 差距皆至少 **5 個百分點**；且
3. 003 的窗口內最大回撤不高於對照的 **1.5 倍**。

門檻與比較計畫 001 相同，**刻意不改**。改門檻需要理由，而「上次沒人通過」不是理由。

**另記一項不參與判定但必須呈報的**：週轉率。§2 的預期就靠它否證。

## 5. 本計畫不涵蓋

- **不開封存區。** 開封次數維持 0。本候選只跑開發區（`tw-alpha-m7-split-01/development`）。
- **不調參。** 21 個場次的再平衡週期是月的慣例換算，不是搜尋出來的；N=10 是 M0 §8 的政策。
- **不主張統計顯著性。**
- **不因結果調整門檻。** §3 的門檻與 001 相同，改它須另寫計畫並說明為何舊的不適用。
