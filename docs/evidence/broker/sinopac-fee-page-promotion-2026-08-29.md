## 0. 這份文件的證據狀態，以及為什麼它低於那份 PDF

[封存的 PDF](sinopac-service-charge-2024-11-28.pdf) 是原始位元組加雜湊——任何人都能重新檢查它是否被改過。

**這一份不是。** 它是一張截圖的**逐字轉錄**，而截圖本身沒有進入倉庫（它在對話裡，不是一個可雜湊的檔案）。證據鏈是：

```
發布者頁面 → 截圖 → Owner → 轉錄
```

每一步都減損可驗證性。**內容是發布者陳述的，我持有的是轉錄。** 兩者不同，所以狀態名稱把它寫出來。

要升到 PDF 那一級，需要把該頁面本身存成有雜湊的檔案。

## 2. 它證實了什麼

**優惠條款首次有發布者的文字支撐。** 在此之前 2 折與低收 1 元只有 `owner-supplied`。

**而且它升級了三個原本只有 Owner 答覆的項目：**

| 項目 | 先前 | 現在 |
|---|---|---|
| 最低收費的計收單位 | `owner-supplied`：每筆委託且成交，不彙總 | **發布者自述**：「**每筆**不足 20 元以 20 元計」 |
| 100 萬電子月交易上限 | `owner-supplied` | **發布者自述**：「線上新開戶（電子月交易100萬內）」 |
| 折讓機制 | PDF 已證實 | 優惠欄再次陳述，兩處一致 |

「每筆」那一條是本專案最承重的條款之一——[M0 §7.2](../m0-project-contract.md) 原本自己標註為歧義（「每筆或每次計費」），而分批出場是否逐筆付最低收費，正是 Phase 0 `consistent_returns` 拒絕率 39% 的成因。**現在它有發布者的字。**

**另外新增一項先前未記錄的排除**：低收 1 元「**外幣ETF除外**」。本專案不交易 ETF（M0 §1 只涵蓋普通股），所以不影響，但記下來。

## 3. 它仍然沒有說的

| | |
|---|---|
| **具體終止日** | 只有「2026 限時優惠」與「2026 優惠活動」，**沒有寫到哪一天** |
| **盤中零股是否適用** | 頁面沒有零股專列。「上市(櫃)股票」是否涵蓋零股，仍只有 `owner-supplied` |
| **超限後如何計費** | 只寫「電子月交易100萬內」，超出後的分級計算仍只有 `owner-supplied` |
| **本專案是否適用** | 優惠限「**線上新開戶**」。Owner 已於 2026-08-29 完成開戶，但**開戶通知信給的是牌告那份 PDF，沒有載明專案費率** |

最後一項是關鍵：**沒有任何文件把這個帳戶與這個優惠連起來。**
