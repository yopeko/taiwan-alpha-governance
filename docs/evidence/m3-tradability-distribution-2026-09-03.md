不是「很少」，是**沒有那個鍵**——全表、每個市場、每一天都沒有。

## 4. 為什麼 `unknown` 是零很重要，以及它為什麼不等於「資料完整」

`asof.py` 只有兩條路通往 `unknown`：

```python
elif membership == "unknown":
    tradability = "unknown"
elif status_state == "no-coverage" or action_state == "no-coverage":
    tradability = "unknown"
```

兩條都是零，所以：**每一個 (市場, 證券, 場次) 的成員狀態、市場狀態與公司行動，都有涵蓋該場次的證據。**

**但這句話只到「有涵蓋」為止。**

上櫃公司行動的最晚生效日是 2026-10-22（預告除權息），八月每個交易日都有——所以我先前預估的「上櫃九天缺口」**不存在**，新的 `m3_actions` 與 `m3_tpex_announcements` 兩個封存把它補上了。

而那 31 筆全額交割仍然是**廠商公司主檔推出來的開放區間**，其結束值是 `--window-end` 給的，不是交易所當日公告。方向保守（把可能已解除的說成仍受限，不會反過來），所以它不會讓不該買的進入股票池——但它不等於「交易所今天說這 31 檔是全額交割」。

**`unknown = 0` 說的是「沒有一格是空的」，不是「每一格都是當日官方證據」。** 那兩件事在這個倉庫裡是分開記的，`evidence_state` 才是回答後者的欄位。

## 5. 守門

`tests/unit/test_measure_tradability.py`，五條，不讀本機資料。其中兩條盯著 `asof.py` 而不是盯著報表：

- 報表列出的五個狀態，必須正好等於 `asof.py` 能產生的五個
- 通往 `unknown` 的分支必須正好是兩條

**若有人加了第三條路徑，`why_unknown` 會少算，而報表照樣印得整整齊齊。** 那是這兩條測試唯一的用途。

另有一條：問一個建置從未到達的場次，必須拒絕而不是回報 0% `unknown`——那與[窗口缺陷](m3-hardcoded-window-end-2026-09-03.md)是同一個形狀，缺的一個月讀起來像一次成功的執行。
