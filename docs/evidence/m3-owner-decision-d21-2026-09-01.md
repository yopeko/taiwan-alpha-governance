# Owner 決定 D21：名額的第二個耦合寫進 M0 §8（`m0-v1.6.0`，2026-09-01）

| 欄位 | 值 |
|---|---|
| 決定 | 把 [D16](m3-owner-decision-d16-2026-08-25.md) 已量出的成本—名額耦合寫入 [M0](../m0-project-contract.md) §8 |
| 契約版本 | `m0-v1.5.0` → **`m0-v1.6.0`** |
| 性質 | **釐清，不是政策變更。** 十一個數值一個都沒有動 |
| 批准 | Product Owner，2026-09-01 |

## 0. 觸發

M0 §8 目前寫著：

> **最大持股數不是獨立參數。** 它等於總開放風險上限除以單筆計畫風險（7.50% ÷ 0.75% = 10）。

**那句話只講了一半。**

名額同時決定**每檔部位有多大**，而每檔部位有多大決定**每筆 NT$20 的最低手續費咬不咬得到**。這是第二個耦合，而它決定的是 §8 底下的任何數字能不能被解讀。

## 1. 這件事 D16 已經量過了

D16 為了解除名額稀缺而把名額由 2 開到 10，重跑後的拒絕碼分佈：

```
233,206  entry:round-trip-cost-exceeds-planned-risk   ← 84% 的訊號
 29,035  entry:position-slots-full
  8,936  entry:no-quantity-satisfies-every-cap
  3,803  entry:cash-cannot-cover-position-and-charged-commission
  1,104  entry:breaches-total-open-risk-cap
```

D16 自己的結論：**「在一萬元規模下，擋住訊號的是成本不是名額。名額只是先前最先撞到的那道牆。」**

**那個發現留在 D16，沒有被寫回契約。** 於是一個只讀 M0 §8 的人，會以為十個名額是一個自由選擇——而它不是，它是一個把 84% 的訊號擋在門外的選擇。

## 2. 算術，因為它不需要爭論

最低手續費 NT$20 在部位達到 **20 ÷ 0.001425 ≈ NT$14,036** 之前一直是實際費率。低於這個門檻，費率不再是 1.425‰，而是 `NT$20 ÷ 部位`。

在 §8 的政策下（NT$10,000，保留 10% 現金）：

```
每檔部位 = 9,000 ÷ 名額數
```

**名額越多，每檔越小，最低費咬得越深。** 名額與成本是反向的，而 §8 現在只寫了名額與風險預算是同向的。

要讓十個名額都跨過 NT$14,036，需要的 NAV 約為 **NT$155,956**——這正是 [ADR-0002](../adr/0002-measurement-scale-separate-from-execution-scale.md) 參考衡量規模取 NT$150,000 的來源，而那個關係目前只存在於 ADR 裡，不在契約裡。

## 3. 為什麼是釐清而不是政策變更

**沒有任何數值改變。** 初始資金、名額、上限、風險目標全部維持。

改變的是：一個已經被量出來、且會改變讀者如何理解這一節的事實，從一份 evidence 文件移進契約本體。

D16 的十一個數值都不動，所以 `test_m0_risk_policy_frozen.py` 的斷言全部應繼續通過——**這是本決定的驗收條件**：若那支測試失敗，代表我改的不是釐清而是政策，本決定即不成立。

## 4. 這與 §7.2 的那句話一起讀

M0 §7.2 已經寫著：

> **任何依此得出的「候選沒有通過」都要連它一起讀**——那可能是被高估的成本擋下的，而不是被策略本身擋下的。

那句講的是**牌告對優惠**的高估。本決定補上的是另一半：**名額數本身也在放大成本**，而它是政策不是市場。

兩者疊加的後果要講清楚：在 M0 規模下，一個候選沒有通過，可能是被高估的費率擋下的，可能是被十個名額造成的小部位擋下的，**也可能真的是策略沒有邊際——而這三者目前分不開。**

分得開的方法已經存在，就是 ADR-0002 的參考衡量規模。**本決定不改變它，只是讓契約自己說出為什麼需要它。**
