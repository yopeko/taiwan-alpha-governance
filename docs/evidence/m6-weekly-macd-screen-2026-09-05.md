## 0. 這份文件不是判定

**沒有預先登錄的計畫，所以下面的數字不判定任何東西。**

M0 §9 要求候選的門檻寫在執行之前。這一次是先實作再執行——Owner 給的是策略
規格，不是一份帶門檻的計畫。所以本文件記錄的是**實作做了什麼、以及它跑出
什麼**，而不是「這個策略通過或沒通過」。

要把它當成候選判定，需要另立一份預先登錄的計畫。

## 1. 規格與它落地成什麼

| Owner 規格 | 落地 |
|---|---|
| 週 MACD 黃金交叉 | 12/26/9，**只用已完成的 ISO 週** |
| 上市近 5 日成交量排行前 30 | TWSE，五個場次的 `volume` 之和，截面前 30 |
| 上市近 5 日三大法人買超排行前 30 | TWSE，五個場次的 `total_net_prior_session` 之和，截面前 30 |
| 報酬／停損 = 2.5 | 停利價 = 進場價 + 2.5 ×（進場價 − 停損價）|

三個條件是 **AND**。停損距離本身**不是**規格的一部分（「報酬／停損」給的是
比值，分母沒有給），所以它維持既有的 `--stop-pct` 參數，本次用 8%。

### 1.1 四個會安靜錯掉的地方

實作時每一個都做了選擇，而每一個選錯都不會報錯：

| | 選擇 | 選錯的後果 |
|---|---|---|
| 週線邊界 | **只用已完成的週** | 收進進行中的那一週，同一條規則會因為執行日是週三還是週五而選到不同的證券 |
| 「黃金交叉」 | **剛穿上去**（上週 ≤，本週 >）| 寫成「在上方」，長多會每一週都觸發，事件變成狀態 |
| 前 30 的分母 | **當日算得出五日總和的上市證券** | 用固定名單，某檔會因為鄰居有 null 而被拱進前 30 |
| 停利與停損同日 | **開盤已在停利價之上 → 停利優先**，其餘停損優先 | 一律停損優先，跳空穿過停利再崩的那天會把帳戶已經賣掉的部位再賠一次 |

最後一項值得展開。停利是一張**限價單**：若開盤就在停利價之上，它在開盤集合
競價已經成交，之後的下跌碰不到停損。原本的 `stop_assumed_to_precede_target_within_a_session: True`
是在**還沒有任何東西會停利**的時候寫下的，現在改成一句帶但書的話。

成交價的規則兩邊一致，**都是「成交在當天真的有過的價格」**：跳空穿過停利
成交在開盤（對帳戶有利），跳空穿過停損也成交在開盤（對帳戶不利）。同一條
原則，不是兩套標準。

### 1.2 停利價由成交價算，不是由訊號算

停損由訊號場次的收盤價定，進場發生在**次日開盤**，所以帳戶實際背的風險是
`成交價 − 停損價`，不是訊號規劃的風險。用規劃風險算停利，會把停利放在一個
帳戶並沒有在承擔的距離的 2.5 倍上。

實測可見：15 筆停利出場的報酬率落在 **18.42% ~ 28.17%**，不是齊一的 20%
——跳空開高使 `(進場−停損)/進場` 變大，開低變小。

### 2.3 成本

M0 規模下 **成本吃掉期初資金的 47.29%**，而最大的單一拒絕理由是
`entry:round-trip-cost-exceeds-planned-risk`（508 次）——一萬元的帳戶要進
一個 8% 停損的部位，來回成本常常大於它計畫承擔的風險，帳本直接拒絕。

這不是這個策略特有的。它是 M0 規模本身的性質，而參考衡量規模存在就是為了
把它分開看。

## 3. 沒有做的事，以及為什麼

- **沒有搜尋停損距離。** 8% 是既有參數，不是為這個策略挑的。試 4%／6%／10%
  會是一次參數搜尋，成本要記在一份預先登錄的計畫裡。
- **沒有搜尋 top N、MACD 參數、累計天數。** 30、12/26/9、5 都是 Owner 給的
  或慣例值，一個都沒有調過。
- **沒有跑封存區。** 開封次數維持 0。
- **沒有和其他候選做兩兩比較。** 那需要[對照比較契約](../contracts/control-comparison-contract.md)的預先登錄。
- **沒有跑隨機同池對照，也沒有跑 2× 成本壓力。** 兩者都是 M0 §8.1a／§9.1
  對一個**要申請 `validated`** 的候選的要求，而這個候選沒有在申請。

## 4. 順帶修掉的兩件事

### 4.1 報告說「未宣告排序函式」，而它有

第一次執行時報告印出「no ranking function declared, so fills followed arrival
order」，`rank_violations_*` 為 −1。但篩選**自己排序**（依五日法人買超）
並填了 `Signal.score`。

`ranking_function` 被綁在 `--ranking` 上，而不是綁在「這次執行實際依什麼排序」。
候選報告契約用那個欄位決定**這一列能不能拿來排候選**，所以那不只是措辭問題。
改成由進場規則自己宣告（`screen:five-session-institutional-net`），
`selection_logic_measured` 隨即變成 `true`。

### 4.2 計畫 005 裡的選擇預算數字是錯的

寫診斷計畫 005 時我寫「選擇預算目前 129 次」。**登錄簿實際是 230 筆。**

129 是 2026-09-03 的數字，而 09-04 的全部重跑加了 #133–#206。
**我引用了里程碑登錄表裡的一個舊數字，而沒有去問登錄簿本身**——
而登錄簿就在磁碟上，一行指令就能數。已訂正。
