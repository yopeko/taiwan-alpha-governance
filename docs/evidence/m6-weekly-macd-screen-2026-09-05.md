## 1. 規格與它落地成什麼

| Owner 規格 | 落地 |
|---|---|
| 週 MACD 黃金交叉 | 12/26/9，**只用已完成的 ISO 週** |
| 上市近 5 日成交量排行前 30 | TWSE，五個場次的 `volume` 之和，截面前 30 |
| 上市近 5 日三大法人買超排行前 30 | TWSE，五個場次的 `total_net_prior_session` 之和，截面前 30 |
| 報酬／停損 = 2.5 | 停利價 = 進場價 + 2.5 ×（進場價 − 停損價）|

三個條件是 **AND**。停損距離本身**不是**規格的一部分（「報酬／停損」給的是
比值，分母沒有給），所以它維持既有的 `--stop-pct` 參數，本次用 8%。

### 1.1 四個會安靜錯掉的地方

實作時每一個都做了選擇，而每一個選錯都不會報錯：

| | 選擇 | 選錯的後果 |
|---|---|---|
| 週線邊界 | **只用已完成的週** | 收進進行中的那一週，同一條規則會因為執行日是週三還是週五而選到不同的證券 |
| 「黃金交叉」 | **剛穿上去**（上週 ≤，本週 >）| 寫成「在上方」，長多會每一週都觸發，事件變成狀態 |
| 前 30 的分母 | **當日算得出五日總和的上市證券** | 用固定名單，某檔會因為鄰居有 null 而被拱進前 30 |
| 停利與停損同日 | **開盤已在停利價之上 → 停利優先**，其餘停損優先 | 一律停損優先，跳空穿過停利再崩的那天會把帳戶已經賣掉的部位再賠一次 |

最後一項值得展開。停利是一張**限價單**：若開盤就在停利價之上，它在開盤集合
競價已經成交，之後的下跌碰不到停損。原本的 `stop_assumed_to_precede_target_within_a_session: True`
是在**還沒有任何東西會停利**的時候寫下的，現在改成一句帶但書的話。

成交價的規則兩邊一致，**都是「成交在當天真的有過的價格」**：跳空穿過停利
成交在開盤（對帳戶有利），跳空穿過停損也成交在開盤（對帳戶不利）。同一條
原則，不是兩套標準。

### 1.2 停利價由成交價算，不是由訊號算

停損由訊號場次的收盤價定，進場發生在**次日開盤**，所以帳戶實際背的風險是
`成交價 − 停損價`，不是訊號規劃的風險。用規劃風險算停利，會把停利放在一個
帳戶並沒有在承擔的距離的 2.5 倍上。

實測可見：15 筆停利出場的報酬率落在 **18.42% ~ 28.17%**，不是齊一的 20%
——跳空開高使 `(進場−停損)/進場` 變大，開低變小。

## 2.4 持股清單與持有長度（2026-09-05 補）

Owner 拿結果去對 XQ，第一個問到的是「有沒有持股清單和持有長度」。**當時沒有**
——報告有 `trades`，但只有進出價與日期，沒有持有長度、沒有停損／停利價、
沒有單筆損益，而期末未平倉只是一個數字。

現已補上：每筆交易帶 `holding_sessions`、`stop_price`、`target_price`；
`open_positions` 由計數改為清單；`scripts/m6/list_trades.py` 產生逐筆表與 CSV。

### 持有長度說了一件事

| | m0 規模 | 參考規模 |
|---|---:|---:|
| 持有中位（場次）| **19** | **20** |
| 持有上限 | 20 | 20 |

| 出場原因 | m0 筆數 | 持有中位 | 毛報酬中位 | 參考 筆數 | 持有中位 | 毛報酬中位 |
|---|---:|---:|---:|---:|---:|---:|

| `target` | 15 | 12 | +20.70% | 28 | 9 | +20.82% |

**20 場次的持有上限是主要出場方式，而它出在大約打平的地方。**

那個 20 是系統既有的預設值，**不在 Owner 的規格裡**——規格給的是 2.5 的報酬
風險比，而這個上限在它兌現之前就把倉位砍掉了。停利只佔 13%（m0）／10%（參考）。

毛勝率 40.4%／36.9%。以 2.5:1 的賠率，四成勝率在原則上是正期望值

**沒有改那個參數。** 它是 Owner 沒有指定的東西，動它就是一次參數搜尋。

## 2.5 一個被 `open_at_end: 1` 藏住的回測器缺陷

期末未平倉原本只是一個數字。展開之後：

```
2448 TWSE  進 2020-12-15 @ 42.33  已持有 983 場次  最後場次無收盤
```

**2448 於 2020-12-23 之後 977 個場次沒有收盤價**，倉庫已標
`suspension-inferred-from-price-absence`、`tradability_state = blocked`。
而它到 2024-12-31 仍在帳上。

原因在出場迴圈的第一行：

```python
for key in list(positions):
    row = rows.get(key)
    if row is None or row.close is None:
        continue
```

**停損要 `low`、停利要 `high`、持有上限要一個成交價。沒有價格，三個出場
全部不會發生。**

| | |
|---|---:|
| 該部位佔期末 NAV | **10.88%**（m0 規模）|
| 以進場價標記 vs 以最後收盤標記 | 差 −2.56 元（期末 NAV 的 −0.05%）|

第二個數字小，是因為進場離停牌只有五個場次；**換一個情形不會這麼小**。
而且那裡還有一個註解與程式碼不一致：註解寫「以前一次的價格標記」，
程式碼用的是 `position.entry_price`——**進場價**。

### 已修（2026-09-05 稍晚），但沒有偽造成交

**帳戶賣不掉一檔沒有在交易的證券，而那是對的。** 錯的是它**安靜地**留著，
而且被以**進場價**標記——那既不是註解說的「前一次的價格」，也不是任何一個
市場印過的數字。

考慮過強制以最後收盤價出場。**否決了**：那要替一檔下市股編造 `MarketConditions`，
而它自己的 docstring 寫著「**沒有查過狀態的呼叫端必須說出來，不能拿到一個
它沒有選擇的寬鬆預設**」。編造市場條件正是那句話擋的事。

改的是三件：

| | |
|---|---|
| 標價 | 由 `entry_price` 改為**最後看到的收盤價** |
| 跳過的出場 | 由靜默 `continue` 改為**記錄拒絕**，並用 `membership_state` 區分停牌與下市 |
| 曝險 | 新增 `nav_in_unquoted_positions`，每個未平倉部位帶 `sessions_without_price` 與 `mark` |

**用生命週期來源判斷，不用「多久沒報價」猜。** 2448 的 `membership_state`
明確是 `delisted`；而量過的停牌長度分佈說明門檻猜不準——98.9% 的停牌 ≤ 7 個
場次，但也有 203、194、144 個場次之後**又恢復報價**的。

修正後同一次執行：

| | 修正前 | 修正後 |
|---|---:|---:|
| 報酬（參考規模）| −28.55% | **−29.43%** |
| 最大回撤 | 33.07% | 33.83% |
| `exit:no-price-cannot-sell-delisted` | **未記錄** | **969 次** |
| `nav_in_unquoted_positions` | 不存在 | **6,582.60**（期末 NAV 的 6.23%）|

差 0.89 個百分點，比先前手算的 −2.56 元大得多——**標價經由 NAV 影響風險預算，
再影響每一次定量**，所以它不是一個一次性的差額。

### 受影響的產物：量過，不是判斷

以 HEAD 的驅動器逐一對照（開發側 split-03，參與率 0.01）：

| 組態 | 修正前 | 修正後 | 未報價持倉 |
|---|---:|---:|---:|
| 動能 12-1 rank-only | −47.0764% | −47.0764% | **0** |
| 候選 006 臂 D | −46.8868% | −46.8868% | **0** |
| 診斷 004 最佳格 | −48.7674% | −48.7674% | **0** |
| 隨機種子 1 | −45.4125% | −45.3443% | 824.60 |
| **低波動 60** | **−38.7386%** | **−35.9886%** | 5,345.35 |

**只有抱得久的策略受影響**，因為抱得久才會抱到停牌。低波動差 **2.75 個
百分點**，隨機組差 0.07。動能、候選 006、診斷 004 **逐位相同**。

所以重跑範圍是**低波動與 20 個隨機種子**，兩個規模。**這比 2026-09-04 的
42 個臂小得多，而範圍是量出來的不是估的。**

既有結論不受威脅：對照 001 的「動能勝 20/20」靠的是 +239.21% 對 −17.79%，
隨機組移動 0.07pp 動不了它；比較 001 的「誰都沒有勝出」也不會因為低波動改善
2.75pp 而翻轉。**但數字要重跑，因為並排的數字必須來自同一個模型。**

改出場語意會讓所有既有產物不可比，[2026-09-04 的停損成交價修正](m6-gapped-stop-fill-2026-09-04.md)
就是那樣，代價是重跑 42 個臂。

## 2.7 持有上限放寬：預期被否證

第 2.4 節寫著「20 場次的持有上限在 2.5R 兌現之前把倉位砍掉」。**量了，那個
推論是錯的。**

參考規模，只改持有上限（試驗 #233–#236，`parameter-search`）：

| 持有上限 | 報酬 | 回撤 | 完成交易 | `stop` | `target` | `max-holding` | 毛勝率 |
|---:|---:|---:|---:|---:|---:|---:|---:|
| **20** | −29.43% | 33.83% | 281 | 109 | 28 | 144 | 36.7% |
| 40 | −28.20% | 32.80% | 249 | 134 | 41 | 74 | 32.9% |
| 60 | −28.52% | 36.30% | 230 | 137 | 44 | 49 | 32.2% |
| **取消** | **−28.19%** | 33.23% | 195 | **145** | **50** | 0 | **25.6%** |

**放寬上限只換到 1.24 個百分點。**

原因看得很清楚：放掉的 `max-holding` **大多不是變成停利，是變成停損**。
停損由 109 增加到 145（+36 筆），停利只由 28 增加到 50（+22 筆），
而毛勝率從 36.7% 掉到 **25.6%**。

**那些在 20 個場次平出場的部位，大多不是在往 +20% 走，是在往 −8.6% 走。**
上限沒有砍掉贏家，它只是提早結束了一批本來會變成輸家的部位——所以拿掉它，
省下的持有上限出場（毛 +0.12%）換成了停損（毛 −8.64%）。

這是本次的第二個被否證的推論（第一個在 §2.5：以為那個未平倉部位只是顯示
問題）。**兩個都是我先講了才去量的**。

## 2.6 和 XQ 對不起來，最可能是這幾項

`list_trades.py` 的說明裡列了七項，每一項都是本倉庫**刻意的選擇**，而每一項
的影響都大於改一條規則：

| | 這裡 | 常見商業回測 |
|---|---|---|
| 價格 | **未還原**官方收盤 | 還原股價 |
| 進場 | **訊號的次一場次開盤** | 常見為訊號當根收盤 |
| 停損成交 | `min(停損, 開盤)` | 常見為停損價 |
| 成本 | 實際券商條款，**單邊最低 NT$20**、賣出稅 0.3%、滑價 | 常為固定費率或忽略 |
| 流動性 | 至多吃當日成交量的 `participation_rate`，不足即拒絕 | 常為無上限 |
| 股票池 | `tradability_state` 逐筆把關（處置、全額交割…）| 常只用上市清單 |
| 定量 | M0 §8 風險預算，部位大小由停損距離決定 | 常為固定張數或固定比例 |

其中**未還原價格**與**成本模型**在這個窗口影響最大：M0 規模下成本吃掉期初的
47.29%，而未還原價格讓每一次除息都變成一次真實的下跌。

## 3. 沒有做的事，以及為什麼

- **沒有搜尋停損距離。** 8% 是既有參數，不是為這個策略挑的。試 4%／6%／10%
  會是一次參數搜尋，成本要記在一份預先登錄的計畫裡。
- **沒有搜尋 top N、MACD 參數、累計天數。** 30、12/26/9、5 都是 Owner 給的
  或慣例值，一個都沒有調過。
- **沒有跑封存區。** 開封次數維持 0。
- **沒有和其他候選做兩兩比較。** 那需要[對照比較契約](../contracts/control-comparison-contract.md)的預先登錄。
- **沒有跑隨機同池對照，也沒有跑 2× 成本壓力。** 兩者都是 M0 §8.1a／§9.1
  對一個**要申請 `validated`** 的候選的要求，而這個候選沒有在申請。

## 4. 順帶修掉的兩件事

### 4.1 報告說「未宣告排序函式」，而它有

第一次執行時報告印出「no ranking function declared, so fills followed arrival
order」，`rank_violations_*` 為 −1。但篩選**自己排序**（依五日法人買超）
並填了 `Signal.score`。

`ranking_function` 被綁在 `--ranking` 上，而不是綁在「這次執行實際依什麼排序」。
候選報告契約用那個欄位決定**這一列能不能拿來排候選**，所以那不只是措辭問題。
改成由進場規則自己宣告（`screen:five-session-institutional-net`），
`selection_logic_measured` 隨即變成 `true`。

### 4.2 計畫 005 裡的選擇預算數字是錯的

寫診斷計畫 005 時我寫「選擇預算目前 129 次」。**登錄簿實際是 230 筆。**

129 是 2026-09-03 的數字，而 09-04 的全部重跑加了 #133–#206。
**我引用了里程碑登錄表裡的一個舊數字，而沒有去問登錄簿本身**——
而登錄簿就在磁碟上，一行指令就能數。已訂正。
