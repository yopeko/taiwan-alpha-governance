# 提案 003：一個賣不掉的部位該怎麼辦（2026-09-05，`awaiting-owner-decision`）

| 欄位 | 值 |
|---|---|
| 日期 | 2026-09-05 |
| 狀態 | **`awaiting-owner-decision`** |
| 起因 | [低波動候選重讀](m7-low-volatility-selects-securities-that-stop-trading-2026-09-05.md)：它期末十個名額全部被下市股佔住 |
| 影響 | **每一個未來的候選**，以及既有產物的可比性 |
| 契約影響 | 視選項而定，見 §4 |

## 0. 事實，先講清楚不含判斷的部分

一檔證券停止報價之後：

- **它不會出場。** 停損讀 `low`、停利讀 `high`、持有上限要一個賣得掉的價，
  三個出場都需要價格。
- **它永久佔用一個名額。** M0 §8 上限十個。
- **它以最後一次成交的價格估值**（2026-09-05 修正前是以進場價）。
- **這些都不是缺陷。** 帳戶確實賣不掉一檔沒有在交易的證券。

實測（開發側 1,458 場次，參考規模）：

| | 動能 12-1 | 低波動 60 | 隨機 20 個中位 |
|---|---:|---:|---:|
| 進場過的證券後來下市 | 1.6% | **15.8%** | 2.0% |
| 期末被鎖住的名額 | 0 | **10 / 10** | 0 |
| 期末 NAV 中的模型估值 | 0 | **79.4%** | 0 |

低波動從 **2022-06-21** 起再也沒有空名額，在窗口剩下的兩年半裡不能再進任何
一檔。完成交易 103 筆對動能的 281 筆。

## 1. 為什麼這需要 Owner 裁決而不是一次修正

**任何一種「讓它出場」的作法，都要替一檔沒有在交易的證券編造一次成交。**

而 `m5/ledger.py` 的 `MarketConditions` 自己寫著：

> Deliberately not defaulted. A caller that has not looked up the state has to
> say so, rather than getting a permissive default it never chose.

編造市場條件正是那句話擋的事。所以這不是「修一個 bug」，是**在兩種都不完美
的模型之間選一個**，而那個選擇會決定每一個未來候選的報酬怎麼算。

## 2. 三個選項

### 甲：維持現況（不出場、以最後收盤價估值）

| | |
|---|---|
| 做什麼 | 什麼都不改。部位留著，名額鎖住，估值用最後成交價 |
| 誠實在哪 | **不編造任何成交。** 帳戶確實賣不掉它 |
| 不誠實在哪 | **估值沒有證據。** 2448（晶電）併入富采 3714，持有人拿到的是新公司的股票，價值可能更高也可能更低；本倉庫的公司行動軌道不涵蓋換股，所以那個「最後成交價」只是最後一個看得到的數字 |
| 代價 | 低波動那種策略的報酬有 79.4% 是這種數字，而報告不會拒絕呈報它 |
| 契約 | 不動 |
| 重跑 | 不需要 |

### 乙：以最後已知收盤價強制出場

| | |
|---|---|
| 做什麼 | 一檔持股的 `membership_state` 變成 `delisted` 之後，以最後已知收盤價認列一次處分，`exit_reason = "delisted-disposal"`，並在報告裡與真正的成交分開統計 |
| 誠實在哪 | **名額被釋放**，帳戶不會在 2022 年就凍住；報酬變成已實現而不是模型估值 |
| 不誠實在哪 | **那筆成交沒有發生過。** 而且它不經過帳本——帳本會拒絕（沒有流動性、`tradability_state` 不合格），所以它必須是一筆繞過 `ledger.execute` 的分錄 |
| 代價 | **所有既有產物不可比**，需要重跑（規模與 2026-09-04 的停損修正相當，42+ 個臂）；且 `m5/ledger.py` 是鏡像檔，繞過它的分錄要寫在驅動器裡，而那會讓「帳本記錄一切」不再為真 |
| 契約 | M5 帳本契約需補一條「非市場處分」；候選報告契約需新增欄位 |
| 重跑 | **需要，全部** |

### 丙：不出場，但把它從可用名額裡拿掉

| | |
|---|---|
| 做什麼 | 部位留著、估值不變，**但不佔用 M0 §8 的十個名額**——鎖住的部位另計，帳戶可以繼續開新倉 |
| 誠實在哪 | **不編造成交**，而且不讓一個模型缺陷把帳戶凍住 |
| 不誠實在哪 | **M0 §8 的十個名額是風險上限，不是操作便利。** 一個真的帳戶抱著十檔下市股再開十檔新倉，它的總曝險就是二十檔——把鎖住的部位排除在名額之外，等於允許曝險超過政策 |
| 代價 | 與 M0 §8 直接衝突，需要 Owner 修改風險政策才成立 |
| 契約 | **M0 §8 要改**，這是三個選項裡唯一動到風險政策的 |
| 重跑 | 需要 |

## 3. 建議：甲，加一條強制呈報

**建議採甲（維持現況），並在候選報告契約新增一個必填欄位：**

```
nav_in_unquoted_positions_pct    期末 NAV 中，由已停止報價的持股貢獻的比例
```

理由三條：

1. **乙與丙都要付出「模型說謊」的代價，而甲只要付出「模型說不知道」的代價。**
   一個說不知道的模型可以被讀者修正；一個編造成交的模型不能。

2. **這個缺陷已經產出了它最有價值的東西。** 低波動系統性挑到會停止交易的
   股票——**那是一個關於排序函式的真實發現**，而它之所以被發現，正是因為
   模型讓那些部位卡住而不是悄悄處分掉。乙會把這個訊號消掉：它會讓低波動看
   起來只是報酬平庸，而不是一個從 2022 年起就不能交易的帳戶。

3. **代價可控。** 甲不需要重跑任何東西，不動 M0 §8，不動鏡像檔；
   而新增的欄位讓 79.4% 這種數字**不可能再被漏看**。

### 3.1 這條建議自己的可否證點

若之後出現一個候選，其 `nav_in_unquoted_positions_pct` 低於 5% 而結論仍然
被鎖住的部位左右，那表示這個欄位不足以呈報問題，甲應被重新考慮。

## 4. 需要你回答的一件事

**採甲、乙、還是丙？**

若採甲，我會：新增該必填欄位、候選報告契約升 v1.4.0、把三份既有證據補上
該欄位的實測值。**不需要重跑。**

若採乙或丙，我會先寫一份落地計畫（含重跑範圍與契約修訂），**不直接動手**
——那兩個都會讓既有產物不可比，而那個決定的成本要先寫下來。
