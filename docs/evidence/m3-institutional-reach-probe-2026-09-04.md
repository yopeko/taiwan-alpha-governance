# 三大法人買賣超能不能成為一個 lane：可以，但格式變過兩次（2026-09-04）

| 欄位 | 值 |
|---|---|
| 日期 | 2026-09-04 |
| 起因 | Owner 問「投信買超前幾名之類的是不是還需要補資料」 |
| 程式 | `scripts/m3/probe_institutional_reach.py` |
| 請求 | **22 次**，6 秒間隔，未寫入任何倉庫 |
| 產物 | `C:\tmp\tw-alpha-m3-institutional\probe-2026-09-04.json` |

## 0. 三句話

1. **TWSE 回到 2012**，比 M3 窗口起點早七年。
2. **欄位數變過兩次：12 → 16 → 19。** 一個建在單一版面上的 lane，跨年跑會把別的欄位讀成別的東西。
3. **已下市公司在它上市期間內確實出現。** 這是最要緊的一題，而答案是好的。

## 1. 為什麼問這三題

與[價格歷史探測](m3-history-reach-probe-2026-09-03.md)同一組問題，因為它們決定的是「這個 lane 做不做得成」而不是「想不想做」。

**第二題尤其**：價格探測發現 TPEx 2010 年前的回應列數不可能是家數，那是舊版面被當前解析器讀成別的東西。

**第三題最要緊**：一份只列還在交易的證券的報表，會**把倖存者偏誤裝進一個看起來像訊號的欄位裡**——比放在價格裡更難發現。

## 2. TWSE：回到 2012，欄位變過兩次

`T86`（三大法人買賣超日報），三月與十月的第三個週三，日期寫死在程式裡：

| 年 | 結果 | 列數 | 欄位數 |
|---|---|---:|---:|
| 2004 | 空 | 0 | — |
| 2008 | 空 | 0 | — |
| 2012-03 | 空 | 0 | — |
| **2012-10** | **有** | 4,528 | **12** |
| 2015 | 有 | 7,865 / 7,130 | **16** |
| 2018 | 有 | 8,882 / 8,451 | **19** |
| 2020 | 有 | 6,915 / 9,651 | 19 |
| 2022 | 有 | 12,996 / 10,090 | 19 |
| 2025 | 有 | 14,310 / 15,397 | 19 |

19 欄版的欄位：

```
證券代號、證券名稱
外資買進股數、外資賣出股數、外資買賣超股數
投信買進股數、投信賣出股數、投信買賣超股數
自營商買進股數、自營商賣出股數、自營商買賣超股數
三大法人買賣超股數
```

**「投信買超」是現成的欄位，不需要推導。**

範例（2409 友達）：投信買賣超 2,519,000 股，自營商買賣超 −6,645,000 股。

### 列數遠多於上市家數

15,397 列對約一千檔上市公司。**那是因為報表含權證、ETF 等**，而權證數量逐年膨脹正好解釋 4,528 → 15,397 的成長。

**若要做這個 lane，範圍過濾要沿用現有的 `tradability_state` 判定，而不是相信報表的列數。**

## 3. TPEx：`openapi` 拒絕，`rwd` 端點可用且更寬

| 候選 | 結果 |
|---|---|
| `openapi/v1/tpex_3itrade_hedge_daily` | **拒絕**——回傳 HTML 而非 JSON |
| `www/zh-tw/insti/dailyTrade` | **可用**，849 列、**23 欄** |

**23 欄比 TWSE 的 19 欄寬**，多出的部分是外資的分項（外資陸資／外資自營等）。**兩個市場的欄位集合不同**，與 [PIT 契約 §6.4.1](../contracts/pit-warehouse-contract.md) 記載的成交量口徑差異是同一類問題：同一個概念在兩個市場裝著不同的東西，而那是官方報表本身的差異。

## 4. 下市檢查：我第一次問錯了市場

第一次探測在五個場次上回報 `3202=無`，而 3202 上市到 2025-04-02。看起來像倖存者偏誤的證據。

**它不是。3202 是上櫃股**（[稽核 §7.5](audit-finmind-crossvalidation-2026-08-21.md)：「只有 OTC上市日，故為 TPEX」），**而我拿證交所的報表去問一檔櫃買的證券。**

問對市場之後：

| 場次 | 列數 | 3202 | 上市期間內 |
|---|---:|---|---|
| 2022-03-16 | 741 | **有**（買 61,000／賣 14,000／超 47,000）| 是 |
| 2024-10-16 | 840 | **有** | 是 |
| 2025-03-19 | — | HTTP 520，**暫時性錯誤不是證據** | 是 |
| 2025-10-15 | 858 | **無** | **否——正確** |

**報表在證券的上市期間內確實列出它，下市之後不列。** 這正是需要的行為。

**這是本週第七次「量到的是真的，但它不是我說的那件事」**，而這一次錯在**問錯了對象**——前六次錯在基準、參考點或驗證方法。

## 5. 若要做這個 lane，四件事

| # | 事情 | 為什麼 |
|---|---|---|
| 一 | **三種版面各要一個解析器**，且以場次日期選擇 | 12／16／19 欄。單一版面跨年跑會讀錯欄位 |
| 二 | **兩個市場的欄位集合不同** | TWSE 19 欄、TPEx 23 欄。強行對齊會製造假欄位 |
| 三 | **排名必須是 T 日收盤後、T+1 進場** | 買賣超收盤後才公布。T 日用 T 日排名是前視 |
| 四 | **範圍用 `tradability_state`，不用報表列數** | 報表含權證與 ETF |

擷取成本：一天一次請求 × 兩個市場，六年約 **3,724 次 ≈ 6 小時**（6 秒間隔）。

## 6. 沒有回答的

- **買賣超的語意。** 自營商的部位含避險，那不是方向性觀點。**這是關於市場的問題，不是關於檔案存不存在的問題**，而本探測只問後者。
- **TPEx 回得到哪一年。** 只在一個場次上試了端點，沒有做年份掃描。
- **消息面分數。** 完全沒有碰——那不是一個資料欄位，是一個模型的輸出，而它的 point-in-time 可得性無法從公開來源確認。
