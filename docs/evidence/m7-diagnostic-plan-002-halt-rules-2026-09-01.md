# 診斷計畫 002：把 M0 §8.1 的停止規則套上去量一次（2026-09-01）

## 0. 為什麼

[對照 001](m7-control-001-result-2026-09-01.md) 量到 `momentum-12-1` 勝過 20 個隨機種子的全部，但**回撤 54.06%** 是隨機中位的 1.94 倍，條件三不通過。

而 [M0 §8.1](../m0-project-contract.md) 寫著：

> 紙上／canary NAV 自高水位回撤達 **5%**：轉 `watchlist` 並停止新部位，等待人工稽核。
> Canary 回撤達 **8%**：硬停止、取消可取消委託並要求人工決定是否退回 paper。

**一個自然回撤 54% 的策略，在 paper 階段就會被 5% 擋下，在 8% 硬停止。它走不到 formal。**

也就是說 **+163.20% 是一個這個帳戶在制度上不可能經歷到的報酬**。

### 而回測從來沒有套用過這兩條線

`m5/ledger.py` 有 `high_water_mark` 與 `drawdown`，但 `run_ledger_backtest.py` **沒有任何東西會因為回撤而停下來**。5% 與 8% 只存在於契約文字裡。

在研究階段這是可辯護的——§8.1 寫的是「紙上／canary」，不是回測。**但後果是：軌道上真正會發生的事，十六次以上的執行沒有一次量過。**

## 1. 量什麼

**只量「會不會被停、什麼時候停」。不量停止之後的權益曲線。**

§8.1 明寫停止後是「**要求人工決定**是否退回 paper」——**恢復規則不存在，它按設計就是人的判斷**。回測若要產出停止後的報酬，就必須發明一條恢復規則，而那會是一個看過結果之後才寫下的自由參數。

因此本次的必報項全部是**無自由參數**的：

| 欄位 | 定義 |
|---|---|
| `sessions_until_first_5pct` | 從窗口起點到首次自高水位回撤 ≥ 5% 的場次數 |
| `sessions_until_first_8pct` | 同上，≥ 8% |
| `date_of_first_8pct` | 首次觸及硬停止門檻的日期 |
| `return_at_first_8pct` | 該時點的累計報酬（自窗口起點）|
| `share_of_sessions_below_5pct` | 停留在高水位下 5% 以外的場次比例 |
| `share_of_sessions_below_8pct` | 同上，8% |
| `first_8pct_before_session_60` | 布林。**這是本次最重要的一欄**，見 §2 |

**刻意不報「被停幾次」。** 一次停止何時結束是人的決定，數「幾次」必須先發明一條重新啟動的規則，而那正是本計畫要避免的那種參數。

## 2. 可被否證的預期

**預期：`momentum-12-1` 會在共同窗口的前 60 個場次之內就觸及 8% 硬停止。**

理由：它的最大回撤是 54.06%，而 8% 只是它的七分之一。一條會走到 −54% 的曲線，很難在前 60 個場次都待在 −8% 以內。

**這個預期會被否證，如果**首次 8% 出現在第 60 個場次之後。那會是好消息——代表大回撤集中在後期，策略至少能跑完 canary 的最短觀察期。

**為什麼是 60**：M0 §9.2 要求 `canary → formal` 原則至少觀察 60 個交易日。**若第一次硬停止早於 60，這個策略連 canary 的觀察期都跑不完**——而那是一句不需要任何新參數就能講清楚的結論。

## 3. 對照組也要套同一組規則

**20 個隨機種子必須用完全相同的方式量。**

理由是這一題會改變結論的方向：

- 若**只有動能**很早被停 → 問題是這個策略的風險輪廓
- 若**隨機組也一樣早**被停 → 問題是**政策與這個組態不相容**（10 個名額、8% 停損、這個股票池），而不是策略

**這兩個結論的下一步完全相反**，所以不能只量動能。

## 4. 執行方式

直接呼叫 `run_ledger_backtest.py --out`（會保存 `equity` 序列），而不是走 `compare_candidates.py`——後者一次跑 8 次回測，而本次每個組態只需要 1 次。

停止事件由權益序列**後處理**得出，不修改回測驅動器。**驅動器不變**，所以既有的 36 次試驗與其產物都不受影響。

範圍：參考衡量規模（依 [ADR-0002](../adr/0002-measurement-scale-separate-from-execution-scale.md)，唯一可作為證據的規模），兩個參與率。21 個組態 × 2 = **42 次執行**。

## 5. 本計畫不涵蓋

- **不涵蓋 M0 規模。** 該規模的報酬數字本來就不得作為證據，而停止規則是對報酬曲線的操作。
- **不涵蓋「停止之後會怎樣」。** 見 §1。
- **不涵蓋修改 5% 或 8%。** 那需要 OOS 協定驗證（§8.1 自己寫的），而封存區只有 382 個場次且不會再生。**用一次不可再生的開封去換一個讓現有結果合格的政策修改，是最差的一筆交易。**
- **不涵蓋任何新的停損或市況規則。** 候選 004b 已經示範過：改停損會同時改變曝險，而曝險的影響比停損本身大。
- **不涵蓋封存區。** 不開封。
