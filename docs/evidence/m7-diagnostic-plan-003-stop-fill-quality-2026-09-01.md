## 0. 我原本要量的東西量不到

[診斷 002](m7-diagnostic-002-halt-rules-result-2026-09-01.md) 之後的下一個問題是：**54.06% 的最大回撤裡，有多少發生在「想賣而賣不掉」的期間？**

動能那一跑有 152 次出場被拒（`exit:limit-price-above-limit-up` 57、`exit:not-tradable-restricted` 95），對比 285 筆完成交易。

**但那個問題用現有資料答不了。** `refusals` 是整跑的彙總，不是逐場次，所以無法把回撤對齊到被拒的那幾天。要那樣做必須改回測驅動器並重跑 42 次。

**先不改驅動器。** 因為現有資料能答一個更直接、且對決策同樣有用的問題。

## 1. 改問這個

**每一筆停損實際成交在哪裡，與 8% 的設計差多少？**

M0 §8 的 7.50% 上限建立在一個假設上：**停損會在停損價成交**。若停損實際成交遠低於停損價，那個上限就只是紙上的。

`trades` 逐筆帶 `entry_price`、`exit_price`、`exit_reason`、`quantity`——**足以直接算**，不需要任何新資料。

### 逐筆定義（無自由參數）

```
設計出場價 = entry_price × (1 − 0.08)
實際出場價 = exit_price
超額損失   = (設計出場價 − 實際出場價) × quantity     ← 為正代表比設計更差
```

只對 `exit_reason == "stop"` 的交易計算（動能 0.01 那跑是 205 筆，另有 80 筆是再平衡出場）。

### 必報項

| 欄位 | 說明 |
|---|---|
| `stops` | 停損出場筆數 |
| `filled_worse_than_stop` | 實際成交低於設計停損價的筆數與比例 |
| `median_slippage_pct` | 相對進場價的中位滑價（負數代表比設計差）|
| `worst_slippage_pct` | 最差的一筆 |
| `excess_loss_as_pct_of_opening_nav` | 全部超額損失合計 ÷ 期初 NAV |
| `filled_better_than_stop` | 成交優於設計停損價的筆數。**必報，否則只看壞的一邊** |

## 2. 可被否證的預期

**預期：超額損失合計會是期初 NAV 的個位數百分比，遠小於 54.06% 的最大回撤。**

理由：停損是逐筆的、金額有界的事件，而最大回撤是整個組合從峰值的回吐——[診斷 002](m7-diagnostic-002-halt-rules-result-2026-09-01.md) 已經指出**主要缺口是參考點錯配**（停損從進場價算、硬停止從高水位算），不是成交品質。

**這個預期會被否證，如果**超額損失達到期初 NAV 的兩位數百分比。那會改變下一步的方向——代表成交品質本身就是主要問題，而移動停損（槓桿 A）不會有用，因為市場根本不讓你在想要的價位出場。

**寫在這裡，因為它決定的是槓桿 A 值不值得做。**

## 3. 對照組一起量

20 個隨機種子同樣計算。若隨機組的超額損失比例相近，代表成交品質是**市場的性質**；若動能明顯較差，代表動能挑到的是流動性較差或波動較大的標的。

## 4. 本計畫不涵蓋

- **不涵蓋「回撤中有多少發生在賣不掉的期間」。** 那需要逐場次的拒絕紀錄，而現有產物沒有。這是本計畫刻意讓步的地方，§0 已說明。
- **不涵蓋未平倉部位。** 期末未平倉 5 檔沒有 `exit_price`，不計入，並在結果中報出數量。
- **不涵蓋 M0 規模。** 產物是參考衡量規模。
- **不改任何程式的行為。** 純後處理。
- **不開封。**
