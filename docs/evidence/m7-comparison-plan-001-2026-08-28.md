# 比較計畫 001：12-1 動能 對 60 日低波動（2026-08-28）

**狀態：`planned`。本文件必須在任何一次比較執行之前提交。**

依[對照比較契約](../contracts/control-comparison-contract.md) §4：契約定義格式，而每一次具體比較還必須在跑之前寫下三件事。這是第一份。

**此刻沒有任何結果存在。** 本文件的用途就是在結果存在之前把話說完。

## 1. 比較哪兩個候選，差異是什麼

| | 候選 A | 候選 B |
|---|---|---|
| 排序函式 | `momentum-12-1` | `inverse-volatility-60` |
| 進場 | 收盤突破前 20 日最高收盤 | 同左 |
| 停損 | 8% | 同左 |
| 持有上限 | 20 場次 | 同左 |
| 股票池 | `all` | `all` |
| 熱身 | 252 場次 | 60 場次 |

**唯一的差異是排序函式。** 名額不足時誰先進場，其餘完全相同。

### 兩者都是先驗，而且量的不是同一件事

`momentum-12-1`：252 場次前到 21 場次前的報酬。Jegadeesh & Titman (1993) 以降。

`inverse-volatility-60`：60 場次日報酬的實現波動度取負。Black (1972)、Haugen & Heins (1975)、Frazzini & Pedersen (2014)。

**動能量的是價格移動了多少，低波動量的是移動得多穩。** 若兩個候選都排序某種過去報酬的變體，那等於同一個候選測兩次。

### 一句必須寫下的話

文獻說的是低波動股票的報酬相對其風險偏高。**它沒有說「剛創 20 日新高的股票之中，波動低的比較好」。** 把兩者組合起來是本專案的動作，不是文獻的主張，所以這個組合要就它自己被評斷。

同一句對候選 A 也成立，M6.3 已經記過。

## 2. 預期哪個方向會贏

**沒有預期。**

寫「沒有預期」不是偷懶。可以編出兩個方向的故事——動能挑最強的突破、低波動挑最不擁擠的突破——而兩個故事都能在事後被拿來解釋任何結果。**一個能解釋任何結果的預期，等於沒有預期，差別只在它會讓人以為自己預測到了。**

## 3. 什麼結果會被算作「沒有幫助」

契約 §4 說這一點最容易被略過，所以先定死。

依契約 §3，一次完整比較是 8 列：2 候選 × 2 規模 × 2 參與率。判定只看**參考衡量規模**的兩列（ADR-0002 決策 1 禁止用 m0 規模的報酬當策略證據）。

**「B 勝過 A」須同時滿足：**

1. 兩個參與率下，B 的窗口內報酬皆高於 A；且
2. 差距皆至少 **5 個百分點**；且
3. B 的窗口內最大回撤不高於 A 的 1.5 倍。

**其餘一律記為「沒有幫助」**，包括：

- 兩個參與率方向不一致——那是對假設敏感，不是對排序敏感；
- 只贏 1 到 2 個百分點——1,584 個場次的一次跑，這種差距與雜訊分不開；
- 報酬贏但回撤是兩倍以上——那不是比較好的排序，是比較大的曝險。

**5 個百分點與 1.5 倍是任意的。** 它們沒有統計依據，唯一的性質是**現在就寫下來了**。一個在看到結果之後才選的門檻，不論多嚴格都沒有這個性質。

## 4. 這次比較不能回答什麼

- **不能回答「低波動在台股有效嗎」。** 這裡測的是一個組合在一個窗口的一次跑。
- **不能回答「哪個候選該進 M7」。** 比較是輸入，不是判決。
- **不能主張統計顯著性。**
- **不能覆蓋整段窗口。** 只涵蓋兩者都在交易的共同窗口，長度由產物自己報告。

## 5. 執行順序

1. 排序函式進 commit；
2. 本計畫進 commit；
3. **然後**才跑 `compare_candidates.py`；
4. 結果另寫一份證據文件，不修改本文件。

第 3 步的順序就是先驗的證據。M6.3 那次我沒有做到——先跑了探針才提交，只能靠自述補救。這次不重蹈。

**本文件在結果產生之後不得修改。** 要改門檻就寫一份新計畫，並說明為什麼舊的不適用；那份說明會與結果同時被讀，這正是重點。
