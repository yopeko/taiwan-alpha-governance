# 回測器讀 23 欄用 12 欄：記憶體減半、速度快四成、輸出逐欄相同（2026-09-04）

| 欄位 | 值 |
|---|---|
| 日期 | 2026-09-04 |
| 起因 | Owner 指出「記憶體只有 32 GB 根本沒有辦法運行」 |
| 變更 | `scripts/m6/run_ledger_backtest.py` 的 `load_dataset` 加欄位投影 |
| 驗證 | 同一組態跑兩次，**逐欄比對 1,221 筆交易與 1,862 個權益點** |
| 試驗登錄 | `probe`，`influenced_a_choice = false` |

## 0. 一句話

**`load_dataset` 讀進資料集全部 23 欄，而驅動器只用 12 欄。** 投影之後 Python 峰值 7.56 GB → **3.85 GB**，耗時 422 秒 → **249 秒**，輸出除了 `built_at` 時戳以外**逐欄相同**。

## 1. 為什麼這件事要緊

這台機器有 31.2 GB 實體記憶體。載入一次日線資料集就要 7.5 GB，所以**一次只能跑一個回測**。

2026-09-03 有兩個背景工作同時跑，兩個都被砍掉，輸出全空、exit code 4，看起來像程式錯誤。**2026-09-04 我在同一台機器上又做了一次**——基準回測跑著的時候我開了第二個量測工作，可用記憶體掉到 **0.5 GB**。這次在它出事之前查了記憶體並停掉第二個，回到 9.0 GB。

**同一個錯犯兩次，而中間我還把第一次寫進了證據文件。** 那不是記性問題，是**這台機器的實際限制沒有被當成限制對待**。

## 2. 變更

```python
DATASET_COLUMNS = (
    "market", "symbol", "session_date",
    "open", "high", "low", "close", "volume",
    "session_state", "tradability_state",
    "limit_up", "limit_down",
)

table = pq.read_table(root / "research_dataset.parquet",
                      columns=list(DATASET_COLUMNS))
```

一行。資料集有 23 欄，這 12 欄是驅動器實際讀的。

## 3. 這個改動唯一的失效模式，以及守著它的測試

**漏掉一欄，它會以 `None` 抵達——而 `None` 與「倉庫本來就沒有這個值」長得一模一樣。**

少一個 `close` 會被讀成「那天沒有報價」，然後那檔證券被靜默跳過。回測照樣跑完、照樣產出報告、照樣通過所有既有測試。

所以清單**不靠記性維護**。`tests/unit/test_dataset_columns.py` 掃描驅動器原始碼裡所有 `row["x"]` 與 `row.get("x")` 形式的存取，**與資料集真正的 schema 取交集**，斷言每一個落在交集裡的欄位都在投影清單中。

schema 從 [`build_research_dataset.py`](../../scripts/m6/build_research_dataset.py) 的 `pa.field(...)` 宣告讀出來，**不需要本機資料**，所以這條守門在快車道裡跑。

另有一條測試盯著掃描本身：**若正則什麼都沒抓到，上面那條就是空的而且會通過**。一個空洞地通過的測試比沒有測試更糟。

## 4. 量測

| | 基準（23 欄）| 投影（12 欄）| |
|---|---:|---:|---|
| Python 峰值 | 7.56 GB | **3.85 GB** | **−49%** |
| 耗時 | 422.0 s | **249.4 s** | **−41%** |
| 完成交易 | 1,221 | 1,221 | 相同 |
| 最終 NAV | 142,800.12 | 142,800.12 | 相同 |

速度變快是意外收穫：少解析 11 欄、少配置 11 個 Python 物件 × 3,928,820 列。

`momentum-12-1`，參考衡量規模 149,717，參與率 0.01，`lookback=20`，`stop_pct=0.08`。

## 5. 我第一次的驗證方法是壞的

第一次比對我把**整份輸出做 sha256**，得到兩個不同的雜湊，然後在輸出裡印了「\*\*\* 不同 \*\*\*」。

**而輸出裡有 `built_at` 時戳。** 那個雜湊在任何兩次執行之間都會不同——**它證明不了相同，也證明不了不同**。

看到雜湊不同時，正確的第一個反應是「我的檢查壞了」，因為同一份輸出的**交易數與最終 NAV 都相同**——那個組合在真正的行為差異下幾乎不可能出現。

改成逐欄比對之後：

```
共 1 處差異
  /built_at
      before: 2026-09-03T17:09:17.181208+00:00
      after : 2026-09-03T17:19:47.013578+00:00
```

**1,221 筆交易、1,862 個權益點、全部 manifest 欄位，其餘完全相同。**

**這是本週第六次「量到的東西是真的，但它衡量的不是我以為的那件事」。** 前五次都是基準或參考點出錯；這一次是**驗證方法本身**——我拿一個包含時戳的雜湊當作等價性證明。
