# M6.3 第一個被排序的候選：12-1 動能，否決（2026-08-26）

## 0. 這份文件記錄什麼

第一個宣告了排序函式、因此第一個能通過 ADR-0002 決策 4 的候選。它被否決了。

它同時是這條管線第一次被一個真候選踩過。**踩出四個瑕疵，全部在管線，不在策略。** 那是本文件比報酬數字更值得讀的部分。

## 1. 為什麼是 12-1 動能

Owner 問的是「一定要生出一個可以量化分數的策略嗎」。要，因為決策 4 要求候選宣告排序函式，而沒有分數就沒有排序。

挑選準則只有一條：**這條規則能不能在打開資料之前就寫下來。**

12-1 動能——252 場次前到 21 場次前的報酬——由 Jegadeesh & Titman (1993) 以降的文獻定下，在別的市場、由沒看過這份資料的人定的。台股 2019-2026 沒有一絲進到那個式子裡。跳過最近一個月不是調參，是文獻本來的形狀：短期報酬會反轉，把最近一個月算進去等於把兩個相反的效應混在一起。

三處是實作的選擇，不是文獻給的，記在 commit `cb0d548` 裡：月換算成場次（252／21 是慣例，仍是一次換算）、歷史深度取 `max(lookback+2, 254)`、分數算不出來時整個候選丟棄而不補零。

### 這裡有一個我沒有做到的程序

先驗的證據應該是 git 的時間順序——排序函式先進 commit，回測才能跑。**我先跑了一次探針才提交。**

所以 `cb0d548` 的時戳證明不了它。補救只能是自述：提交的函式與跑過的那一份逐字相同，跑完之後沒有動過。這比 git 順序弱。記在這裡，是為了不讓後來的人把那個時戳讀得比它實際上更有力。

## 2. 結果

窗口 2019-01-02 → 2026-08-03，1,840 場次，2,108 檔證券。

| | m0 執行規模 | 參考衡量規模 |
|---|---:|---:|
| 期初資金 | 10,000 | 149,717 |
| 報酬 | **−51.34%** | **−2.33%** |
| 最大回撤 | 51.34% | 55.40% |
| 完成交易 | 163 | 1,204 |
| 實扣成本 | 6,737 | 99,152 |
| 成本／期初 | 67.4% | 66.2% |
| 成本／成交額 | **3.39%** | **0.33%** |
| 拒絕總數 | 238,863 | 237,349 |

依 ADR-0002 決策 1，**m0 規模那個 −51.34% 不得作為策略優劣的證據**。它主要在講帳戶太小：成本吃掉期初資金的 67.4%，而同一策略在參考規模的成本佔成交額只有 0.33%，相差 10.2 倍。這正是該 ADR 存在的理由，這份報告只是又量了一次。

參考規模的 −2.33% 才是可以拿來讀的數字。它是負的。

### 與未排序探針的比較，以及為什麼不能直接比

| | 未排序探針 | 12-1 動能 |
|---|---:|---:|
| 參考規模報酬 | −2.46% | −2.33% |
| 參考規模回撤 | 18.47% | **55.40%** |
| 參考規模成交 | 1,235 | 1,204 |

排序讓報酬幾乎沒動，回撤變成三倍。

**但這兩欄不是同一段路。** 動能需要 252 場次熱身，排序版實質上到 2020-01-16 才開始交易，吃掉窗口的 13.7%。兩次跑的起點不同、經歷的市況不同，所以上表只能當作「換了排序之後不是同一個東西」的提示，不能當作排序的效果量測。

要真的比，需要兩邊都從 2020-01-16 起算。**本文件不做這件事**，理由見第 5 節。

## 3. 判定：`selection-logic-measured`，兩個規模都是

| 規模 | 稀缺違反 | 塞不下違反 | 判定 |
|---|---:|---:|---|
| m0 執行 | **0** | 53 | `selection-logic-measured` |
| 參考衡量 | **0** | 123 | `selection-logic-measured` |

判定為真只說了一件事：**這次跑的是一條選股規則，不是先到先得。** 它沒有說那條規則好。它確實不好。

「塞不下」的違反是最高分那一檔進不了帳戶：

| 理由碼 | m0 | 參考 |
|---|---:|---:|
| `cash-cannot-cover-position-and-charged-commission` | 16 | 110 |
| `round-trip-cost-exceeds-planned-risk` | 21 | 5 |
| `no-quantity-satisfies-every-cap` | 14 | 7 |
| `breaches-total-open-risk-cap` | 2 | 1 |

兩個規模的形狀相反。小帳戶被**來回成本**擋下最高分的那一檔，大帳戶被**現金**擋下。

分母要用能交易的場次，不是 1,840——熱身之後約 1,588 個。53／1,588 = 3.3%，123／1,588 = 7.7%。

### 稀缺的那兩個 0 不是發現

排序正確時它必然是 0，而那是迴圈的算術：訊號依分數由高到低走訪，進場迴圈中 `positions` 只增不減（出場在更早一步跑完），名額一旦滿了就不會放開，之後不會再有任何成交——所以稀缺型拒絕在結構上不可能後面跟著一筆開倉。

我在報給 Owner 時把這兩個 0 說成「六年下來一次都沒有違背排序」，那是錯的。詳見第 4 節第三項。

## 4. 這個候選踩出來的四個瑕疵

四個都在管線，都由這次跑出來，都已修。這是本文件的主要內容。

### 4.1 已持有被記成名額已滿

同一檔再次發出訊號、分數很高、因為**已經持有**被拒，舊碼記成 `position-slots-full`。於是「名額滿了擋下高分」——可是我們正握著那一檔。排序是被遵守了。

**帳戶自己最好的部位在製造違反。** 拆出 `entry:already-held` 後違反數由 70／375 降到 53／123。修於 `328c403`。

### 4.2 容量把兩件事黏在一起

判定原本看「容量」違反總數。而 53 與 123 之中稀缺佔 0，塞不下佔全部——**判定完全由塞不下決定，而那一項講的是帳戶規模，正是 ADR-0002 的主題，不是選股邏輯的缺陷。**

拆成稀缺與塞不下，判定只看前者。分界不是取捨，是可查的：`plan_position` 在讀到候選價格之前就返回的是稀缺，讀了價格或停損才返回的是塞不下。`round-trip-cost-exceeds-planned-risk` 因此改邊——8/25 歸為容量的理由「它隨帳戶規模變動」沒錯，但它同時也隨證券變動。修於 `d9cc427`，契約升 v1.2.0，ADR 決策 4 第二次修訂。

### 4.3 我把算術報成發現

見上一節。那句話錯在把「結構上不可能非零」說成「六年下來表現良好」。

後果不只是說錯：一個結構上不會失敗的檢查，在真實回測裡沒有人能看見它動。所以比較邏輯由迴圈抽成 `count_rank_violation`，`tests/unit/test_rank_violation_check.py` 12 條逼它兩邊都動——高分被擋低分成交要抓到、反過來要放行、平手不算違反、兩個集合必須互斥。

那個計數的正確身分是**排序有沒有真的被套用的守門員**，它變成非零只有一種情況：排序壞了，或改用到達順序。

### 4.4 三處版本漂移，同一種

| 位置 | 宣告 | 實際 |
|---|---|---|
| `CANDIDATE_REPORT_CONTRACT` | v1.0.0 | 契約文件已 v1.1.0，報告已帶 v1.1.0 欄位 |
| `CANDIDATE_REPORT_SCHEMA` | 1.0.0 | 欄位已換過一輪 |
| `strategy.note` | 「a pipeline probe, not a proposal」| 已經是一個宣告了排序的候選 |

三處都是「沒有人盯著這一對」。前兩者對齊到 v1.2.0 並補上 `test_the_producer_declares_the_version_the_contract_carries`；`note` 改為由 `ranking_function` 導出而非寫死。

一份報告宣告錯的版本，會讓想確認它符合哪個契約的讀者拿到錯的答案——而這正是這整套版本欄位存在的唯一理由。

## 5. 否決，以及沒有做的事

**12-1 動能排序的 20 日突破，在六年窗口的兩個規模下都是虧的。候選否決。**

沒有做而且刻意不做的：

- **不調參。** lookback、stop、持有上限、動能的 252／21 都沒有動過。一個先驗排序在跑完之後被調，就不再是先驗。
- **不做熱身對齊的重跑。** 那會回答「排序有沒有幫助」，是個好問題，但它需要先決定對照組怎麼設，而那個決定會被剛剛看到的結果污染。
- **不換排序函式再試一次。** 這正是 M6.2 已經量過的路：試到一個能過的排序，等於用這個窗口挑排序。

第一個資料點的用途是它是第一個，不是它是好的。

## 6. 這份報告可以支撐什麼

可以：
- 管線從資料集到候選報告全程可跑，且被契約強制。
- ADR-0002 決策 3 的兩規模差距在真候選上量到 10.2 倍。
- 決策 4 的判定路徑首次被走完，並在走的過程中暴露 4.1 與 4.2。

不可以：
- 不能說 12-1 動能在台股無效。這裡測的是「12-1 動能排序 + 20 日突破進場 + 8% 停損 + 20 場次持有上限 + M0 §8 風險政策」這一整個組合在一個窗口的一次跑，其中只有排序是先驗的。
- 不能說排序讓回撤變差。熱身讓兩次跑的窗口不同。
- 不能把 m0 的 −51.34% 當策略證據（ADR-0002 決策 1）。
