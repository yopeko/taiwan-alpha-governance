## 0. 為什麼是這個，而不是直接回測一個策略

法人資料[已經接進資料集](m6-institutional-into-dataset-2026-09-05.md)，下一步的
自然衝動是拿「投信買超前 N 名」跑一次回測。**不做，理由有三個而且都是量出來的：**

| 來源 | 量到的 |
|---|---|
| [診斷 002](m7-diagnostic-002-halt-rules-result-2026-09-01.md) | 帳戶 **82.2%** 的場次在高水位 −8% 之外，而 **20/20 隨機對照最後也全部跨過 8%** |
| [診斷 004](m7-diagnostic-004-reachability-result-2026-09-02.md) | 十四格參數全部在 8% 之上，修正後最低 **15.34%** |
| [排名品質 001](rank-quality-001-2026-08-28.md) | `momentum-12-1` 的排序能力**與零無法區分**（IC −0.0080，t −0.56）|

前兩者說：**卡住的不是排序函式**，是這個組態本身在 M0 §8.1 下無法運作。

第三者說得更難聽：動能跑過**三次比較**才有人問它排得準不準，而答案是不準。
一次回測的報酬混合了排序品質、成本、時機與市況；**在混合之前先問排序品質，
是把最便宜的那個問題先問掉。**

若四條訊號的 IC 都與零無法區分，**就沒有任何候選值得登記**——而我們用一次診斷
的代價知道了，不是用一族候選。

## 1. 四條訊號，定義寫死在這裡

全部讀 `..._prior_session` 欄位，即場次 T−1 公布的報表
（[為什麼](m6-institutional-into-dataset-2026-09-05.md) §1）。分數愈高排愈前。

| 名稱 | 定義 | 需要的歷史 |
|---|---|---:|
| `investment-trust-net` | `investment_trust_net_prior_session` | 1 |
| `investment-trust-net-5` | 最近 5 個場次的 `investment_trust_net_prior_session` 之和 | 5 |
| `foreign-net-5` | 最近 5 個場次的 `foreign_net_prior_session` 之和 | 5 |
| `institutional-net-turnover` | `total_net_prior_session ÷ volume`，同一場次（T−1）| 1 |

### 1.1 null 的處理，先講定

- **任一必要值為 null → 分數為 `None`**（不參與該截面的排序），不填 0。
  null 的意思是「那天沒有被報價」，把它當成「沒有法人單」會把停牌與退市的
  證券混進排序。
- **值為 0 是一個數字**，照常參與。
- `institutional-net-turnover` 的 `volume` 為 null 或 **0 時分數為 `None`**：
  除以零不是一個很大的數，是一個沒有意義的數。
- 5 日累計要求 **5 個場次全部非 null**，不足即 `None`。不用可得的部分補，
  因為 3 天的和與 5 天的和不是同一個量，混在一個截面裡排序是在比不同的東西。

### 1.2 前三條與第四條問的不是同一件事

**原始股數大部分是一個規模代理變數。** 台積電的投信買超永遠會壓過小型股，
所以「投信買超前 N 名」照字面實作，排出來的前段班很可能只是大型股。

第四條把成交量除掉。**兩種都量，因為只量前三條而結果為正時，我分不出那是
法人資訊還是大型股效應**——而那個分不出來，正是這份計畫要避免的東西。

## 2. 量測參數，與排名品質 001 完全相同

不動任何一個，因為改了就沒辦法和動能、低波動並排：

| 參數 | 值 |
|---|---|
| 截面間隔 | 每 **21** 個場次 |
| 未來報酬 | **21** 個場次 |
| NDCG@N | **N = 10**（十名額帳戶只碰得到前十名）|
| 度量 | Rank IC（Spearman）、t 統計、NDCG@10、分位單調性 |

### 2.1 一個必須連結果一起讀的限制

未來報酬用**未還原**收盤價，因為本倉庫沒有還原序列，而 M0 禁止在沒有書面方法
的情況下自行推導。除息日會出現人為下跌，**高殖利率證券的未還原未來報酬系統性
偏低**。

這對本計畫**特別要緊**：法人買超與高殖利率大型股正相關並非不可能，
所以若四條訊號的 IC 為負，**那個負值有一部分可能是股息，不是排序能力**。
方向已知、不做修正、連結果一起呈報。

## 3. 可被否證的預期

寫在執行之前，且**允許事後被打臉**：

| # | 預期 | 什麼會否證它 |
|---|---|---|
| 1 | `investment-trust-net` 的 IC 與零無法區分（\|t\| < 2）| \|t\| ≥ 2 |
| 2 | `institutional-net-turnover` 的 \|IC\| **大於**前三條的任何一條 | 它反而最小 |
| 3 | 5 日累計的 \|t\| 大於單日（累計降噪）| 單日反而更強 |
| 4 | 前三條的分位單調性**不成立**（規模效應非單調）| 三條都單調 |

**預期 1 與 2 互相矛盾嗎？** 不：1 說字面版沒有資訊，2 說去掉規模之後的版本
資訊較多。兩者可以同時成立（前三條 t 小、第四條 t 大），也可以同時被否證。
**這個相容性檢查是[診斷 004](m7-diagnostic-plan-004-reachability-2026-09-02.md) §3
學到的**——候選 006 寫下兩個互相矛盾的預期而當時沒有發現。

## 4. 判定：這份計畫不判定任何策略

**只有一個判定，而且它是關於「要不要繼續」：**

> 四條訊號中若**沒有任何一條**的 \|t\| ≥ 2，則**不登記任何以法人買賣超為排序
> 函式的候選**，本方向結案，結論寫進證據文件。

若有一條或多條 \|t\| ≥ 2：**那也不構成一個候選**。它只解除「值不值得寫一份
候選計畫」這個前置，而候選計畫要自己預先登錄自己的門檻。

**t ≥ 2 不等於能賺錢。** 低波動的 IC 是 +0.0723、t +3.18，而它在
[比較 001](m7-comparison-001-result-2026-08-28.md) 裡誰都沒有勝出，
修正後報酬 −2.04%。排得準與賺得到之間隔著成本、名額與 §8.1，
而那三樣[已經被量過了](m7-diagnostic-004-reachability-result-2026-09-02.md)。

## 5. 必報項

- 四條各自的截面數、平均 IC、t、NDCG@10、五個分位的平均**與中位數**
- **平均與中位數方向不一致時，兩個都報並解釋**
  （[排名品質 001 §2](rank-quality-001-2026-08-28.md) 就是這樣才問出低波動異象）
- 逐年 IC 與符號一致性、擴張平均 IC
- 每條訊號**因 null 而未計分的比例**——若某條有一半的證券算不出分數，
  它的 IC 是在一個被篩過的池子上量的，那件事必須看得見
- 與 `momentum-12-1`（−0.0080）、`inverse-volatility-60`（+0.0723）並排
- **每條訊號選到的證券後來下市的比例，與 20 個隨機種子並排**（2026-09-05 新增）——[低波動被量到 15.8%，高於 20/20 個隨機種子、是隨機中位的 8 倍](m7-low-volatility-selects-securities-that-stop-trading-2026-09-05.md)，而它的 IC 是正的。**IC 高不代表組合能運作**，所以這一欄必須並排呈報。

## 6. 本計畫不涵蓋

- **不跑任何策略**、不產生任何候選報告、不動封存區
- **不測其他四個度量**（外資自營、自營自行、自營避險、外資合計）——
  它們在法人表裡，需要時另立計畫
- **不測其他累計天數**。5 日是事先選的，**不做 3／5／10／20 的掃描**：
  那會變成一次參數搜尋，成本記在別的地方
- **不做任何組合**（法人 × 動能之類）。組合是候選的事

## 8. 執行前必須先做的事

排序函式原本的簽章是 `(closes, i, **_identity)`——**只拿得到收盤價**。
四條訊號要讀 `..._prior_session` 與 `volume`，所以簽章必須擴。

**2026-09-05 已完成。** 簽章改為 `(bars: list[Bar], i, **identity)`：傳整列
而不是多傳幾個平行串列，因為兩個平行串列會有一天差一格，**而那一格不會報錯，
只會讓結果變漂亮**。傳整列之後，價格與法人數字的對齊是結構性的。

**這是一次行為保留的改動，而且是驗過的**，因為既有兩條若動了一個小數位，
所有既有比較都不可比而且不會有任何錯誤訊息：

| | 2026-08-28 紀錄 | 改動後重跑 |
|---|---|---|
| `inverse-volatility-60` | 66 截面／+0.0723／t +3.18／NDCG 0.2962 | **完全相同** |
| `momentum-12-1` | 56 截面／−0.0080／t −0.56／NDCG 0.3891 | **完全相同** |

回測側同組態重跑，**欄位差異只有 `built_at`**。

驅動器裡決定歷史深度的 `if ranking_name == ... elif ...` 鏈同時被換成
`RANKING_HISTORY_SESSIONS` 宣告表——漏掉一條排序函式，它會拿到進場規則的
深度，而**對五日累計而言那足以讓每一檔都回 `None`：沒有錯誤、沒有分數、
執行完產出一份什麼都沒排的報告**。一條測試盯著每個名字都有宣告。

**本計畫現在可以執行。**

同時已發現並修掉一個相關缺陷：`rank_quality.py` 自 2026-09-04 的 `Bar` 改動起
就無法執行（`row["close"]` 對一個 `__slots__` 物件下標），而守門沒抓到，
因為那條規則只掃 `run_ledger_backtest.py` 一個檔案。已修，並把規則改為
**掃描每一個使用 `load_dataset` 的模組**。
