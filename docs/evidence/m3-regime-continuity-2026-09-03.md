# 我說現有窗口跨過兩個制度變更而沒有分段。量了，那個疑慮不成立（2026-09-03）

| 欄位 | 值 |
|---|---|
| 日期 | 2026-09-03 |
| 起因 | Owner 問：「不同時期市場的屬性也會發生改變，同一個策略可能跑出不同結果」 |
| 程式 | `scripts/m3/measure_regime_continuity.py` |
| 產物 | `C:\tmp\tw-alpha-m3-regime\continuity-2026-09-03.json` |
| 資料 | 已封存的 `TWSE-PRICE-HIST` blob，1,862 個場次，**未擷取任何東西** |

## 0. 一句話

**我提的疑慮量不到。** 對撮合機制最敏感的指標，在兩個制度變更前後的水準位移是 **+2.4%** 與 **+0.7%**，而月度跳變的中位數是 **3.0%**——**比一個典型月份的雜訊還小**。

## 1. 這個問題怎麼來的

Owner 指出一件對的事：市場屬性會隨時期改變，所以同一個策略在不同時期會跑出不同結果。

我先查了，發現[M4 契約 §1.2.1](../contracts/m4-market-rules-contract.md) **在 2026-08-22 就把這件事寫下來了**——漲跌幅 2015 年中由 7% 改為 10%，而 `PRICE_LIMIT_RATE = Decimal("0.10")` 是一個沒有日期的常數，所以契約明文禁止把它套用到 2015 年中之前。**我前一則建議「回補到 2008」因此是錯的**，那 11 年裡有約 1,822 個場次落在 7% 時期。

然後我提出一個更大的主張：**現有的 2019–2026 窗口本身已經跨過兩個制度變更**——逐筆交易取代集合競價、盤中零股交易開辦，兩者都在 2020 年——**而所有候選結果都是把變更前後混在一起算的**。

**本文件是去量那個主張，而它不成立。**

## 2. 方法，沿用 M4 §1.2.1 建立的那一套

取變更前後的場次，看行為有沒有階梯式跳變。資料來自 TWSE `MI_INDEX` 回應的 **table 6「大盤統計資訊」**——一天一列，含成交金額、成交股數、成交筆數，全市場一般股票。與[指數表](m7-benchmarks-and-cost-stress-2026-09-03.md)同一批已封存、已驗證雜湊的 blob，**沒有擷取任何東西**。

三個量：

| 量 | 對什麼敏感 |
|---|---|
| 每日成交筆數 | **活動量**。崩盤會暴增 |
| **平均每筆股數** | **撮合機制**。逐筆交易拆碎委託，集合競價批次撮合 |
| 平均每筆金額 | 同上，以金額表示 |

### 為什麼「變更當月有跳變」不算數

**逐筆交易在 2020 年 3 月，COVID 崩盤也在 2020 年 3 月。** 那個月跳起來的指標有兩個候選成因，而日期本身分不出來。

**這與[診斷 002](m7-diagnostic-002-halt-rules-result-2026-09-01.md) 第一個答案錯掉的形狀完全相同**——策略的熱身在崩盤前兩週結束，量出來的數字是關於崩盤的。

所以量兩件事而不是一件：

1. **變更當月的跳變異不異常**——放進所有 92 個月度跳變的分佈裡排名，而不是跟空氣比
2. **有沒有永久的水準位移**——機制改變會移動水準並留在那裡，崩盤會暴衝然後回落

**只有第二件能定論。**

## 3. 結果

### 3.1 跳變排名（92 個月度跳變）

| 指標 | 2020-03 | 2020-10 |
|---|---|---|
| 每日成交筆數 | 43.0%，第 **97** 百分位 | 8.1%，第 45 百分位 |
| **平均每筆股數** | **3.5%，第 57 百分位** | **2.4%，第 39 百分位** |
| 平均每筆金額 | 12.2%，第 93 百分位 | 0.8%，第 7 百分位 |

**盤中零股（2020-10）三個指標分別在第 45、39、7 百分位——比典型月份還平靜。**

逐筆交易（2020-03）有兩個指標異常，**但機制敏感的那一個沒有**。

### 3.2 水準位移（前後各 12 個月中位，排除變更當月）

| 指標 | 2020-03 | 2020-10 | 月度跳變中位 |
|---|---:|---:|---:|
| 每日成交筆數 | +74.0% | +77.4% | 8.7% |
| **平均每筆股數** | **+2.4%** | **+0.7%** | **3.0%** |
| 平均每筆金額 | +6.2% | +9.9% | 5.7% |

**每日成交筆數的 +74% 是 2020–2021 的散戶熱潮，不是機制。** 若是撮合機制造成，平均每筆股數會同步下移——它沒有。

**平均每筆股數的位移 +2.4% 與 +0.7%，都小於月度跳變的中位數 3.0%。** 一個比典型月份雜訊還小的位移不是階梯。

逐月看得更直接：

```
2020-02  2,452
2020-03  2,538   ← 逐筆（推定）
2020-04  2,451   ← 回到變更前
...
2020-09  2,720
2020-10  2,655   ← 零股（推定）
2020-11  2,615
```

**2020-03 之後就回去了。機制造成的位移不會回去。**

## 4. 所以我的主張錯在哪

錯在**把「日曆上跨過了變更」當成「資料上跨過了斷點」**。

前者是事實，後者要量。**而量出來是連續的。**

現有的候選結果（003、005、006、對照 001、診斷 002–004）**不需要因為這兩個變更而分段重讀**。

## 5. 這個量測不能回答什麼

**這是全市場日彙總，它對盤中一無所知。**

- **盤中成交行為有沒有改變**——滑價、部分成交、排隊位置——需要本專案沒有的逐筆資料
- **盤中零股在 2020 年下半之前能不能執行**——那是**規則問題，有生效日，不是量測問題**

第二項仍然是活的，而且它對本專案特別要緊：**M0 一萬元規模下每一個部位都是零股。** 若盤中零股在該日之前不存在，那段期間的 M0 規模回測模擬的是一個當時不存在的機制。

**但這不是新洞。** [M0 §8](../m0-project-contract.md) 已經把「零股成交證據」列為真實 canary 的**未解除阻擋**（D18 第二項）。本文件只是把它指得更精確：不只是「一筆零股委託會不會成交」，還有「那個交易時段當時存不存在」。

**兩個變更的生效日本身也沒有查證過。** 程式與輸出全部標 `presumed`。這不影響結論——永久位移不論從哪個月開始都看得見，而掃描是對全部 92 個月做的，沒有被告知該看哪裡。

## 6. 一件方法上的事

我第一次量的時候只測了自己猜的那兩個日期。**那是先射箭再畫靶。**

改成掃描全部 92 個月之後，最大的三個跳變是 2026-01（+69.8%）、2021-04（+57.8%）、2020-03（+43.0%）——**全部是活動量，沒有一個在我猜的機制上**。
